## 1. ตรรกะวงจรชีวิตคัมภีร์มหาวิถี

* **ที่มาและปัญหาเดิม:**  
  คัมภีร์มหาวิถี (`MANUAL_PATH_*`) เมื่อได้มาจากการเสก, การบริจาค, หรือแหล่งอื่นที่ไม่ได้ผ่านคาราวาน จะตกค้างอยู่ในคลังสำนักเฉยๆ โดยไม่มีใครหยิบไปใช้ ขณะเดียวกันหากได้คัมภีร์ซ้ำกับวิถีที่สำนักมีอยู่แล้ว ก็ไม่มีระบบนำไปใช้ประโยชน์

* **โครงสร้างตรรกะที่ควรเป็น (Target Logic Pipeline):**

```
 [แหล่งที่มาของคัมภีร์]
 (ซื้อจากคนนอก / ศิษย์บริจาค / สำรวจพบ / เสกผ่าน Editor)
           │
           ▼
   [คลังสำนัก (Vault / Stock)] ── คัมภีร์เข้าสู่คลังในฐานะไอเทมของกลาง
           │
           ▼
  [เจ้าหน้าที่หอคัมภีร์ตรวจสอบ]
           │
     ┌─────┴──────────────────────────────┐
     │ หอคัมภีร์ "ยังไม่มี" วิถีนี้          │ หอคัมภีร์ "มีวิถีนี้อยู่แล้ว"
     ▼                                    ▼
[ขึ้นทะเบียนเข้าหอคัมภีร์]            [เปลี่ยนเป็นสินค้าส่งออก]
- เบิกคัมภีร์ออกจากคลัง (หายไป)        - คงอยู่ในคลังเพื่อการค้า
- ปลดล็อกใน SECT.PATH_LIBRARY         - นำไปวางขายในร้านค้าสำนัก หรือ
- สมาชิกทุกคนเรียนได้ถาวร              - ขายให้คาราวานคนนอกเป็นศิลาปราณ
```

* **ผลลัพธ์เชิงระบบ:**
  1. คลังไม่เกิดขยะไอเทมตกค้าง
  2. หอคัมภีร์กลายเป็นศูนย์กลางองค์ความรู้ถาวรของสำนัก
  3. คัมภีร์เล่มซ้ำมีมูลค่าทางเศรษฐกิจในการสร้างรายได้เข้าสำนัก

## 2. บั๊กวิกฤตที่ 1: ระบบถ่ายทอดวิชาข้ามสายบำเพ็ญ

* **ระดับความรุนแรง:** P0 (Logic & Progression Integrity)
* **พิกัดที่พบ:** 
  1. `GAME_SOURCE/js/sect.js` (บรรทัด 5068–5077 ในฟังก์ชัน `MENTORSHIP.transmitQi`)
  2. `GAME_SOURCE/js/sect.js` (บรรทัด 3580–3597 ในฟังก์ชัน `EDITOR.directCatalogAction: teach`)
* **พฤติกรรมผิดปกติ:**
  - ในฟังก์ชัน `MENTORSHIP.transmitQi` ลูปสืบทอดวิชาของอาจารย์สู่ศิษย์ ตรวจสอบเพียง:
    ```javascript
    if (tObj && !tObj.innateOnly && !disciple.cult.techs.includes(tid))
    ```
    โดย **ไม่มีการตรวจสอบความสอดคล้องของวิถีหรือสายย่อย** (`CULT.isSubCompatible`)
  - ส่งผลให้วิชาเฉพาะสายย่อยทั้ง 126 รายการ สามารถถูกถ่ายทอดให้ตัวละครที่เดินคนละวิถีได้อย่างอิสระ (ทดสอบแล้วสำเร็จ 126/126 รายการ)
* **ขัดแย้งกับกติกา:** วิชาเฉพาะสายย่อยต้องเกิดจากการตื่นรู้และฝึกฝนตามสายที่กำหนดเท่านั้น อาจารย์สายกระบี่ไม่ควรสามารถถ่ายทอดวิชาเฉพาะสายกระบี่ให้ศิษย์สายพุทธหรือสายกู่ได้
* **แนวทางแก้ไข:**
  - เพิ่มเงื่อนไขตรวจสอบความเข้ากันได้ของสายวิชาก่อนทำการถ่ายทอด:
    ```javascript
    if (tObj && !tObj.innateOnly && !disciple.cult.techs.includes(tid) &&
        CULT.isSubCompatible(tObj, disciple.cult.sub) &&
        (tObj.path === 'ANY' || tObj.path === disciple.cult.path))
    ```

## 3. บั๊กวิกฤตที่ 2: ระบบ Save/Load ไม่ตรวจสอบ Schema Version

* **ระดับความรุนแรง:** P0 (Save File Corruption Risk)
* **พิกัดที่พบ:** `GAME_SOURCE/js/sim.js` (บรรทัด 797–842 ในฟังก์ชัน `SIM.deserialize`)
* **พฤติกรรมผิดปกติ:**
  - `SIM.deserialize` ตรวจสอบเฉพาะ Fingerprint ของแกนมนุษย์ (`s.hc !== HC.FINGERPRINT`)
  - ตัวแปร `s.schemaVersion` และ `s.v` ถูกใส่ไว้เพียงใน `knownKeys` เพื่อป้องกันไม่ให้ขึ้น Error แต่ไม่มีโค้ดเปรียบเทียบเวอร์ชันจริง
  - เมื่อทดลองนำเซฟปลอมเวอร์ชัน `9999.0.0` มาโหลด ตัวเกมยอมโหลดขึ้นมาทำงานโดยไม่แจ้งเตือนใดๆ
  - เมื่อระบบทำการ Autosave ตัวเกมจะแอบเขียนทับเวอร์ชันกลับเป็น `2.0.0` ทันที
* **ความเสี่ยง:** เสี่ยงต่อการเปิดไฟล์เซฟจากเกมเวอร์ชันใหม่ในอนาคตที่โครงสร้างฐานข้อมูลเปลี่ยนไปแล้ว ทำให้ข้อมูลและ State ของเกมเสียหายอย่างเงียบๆ
* **แนวทางแก้ไข:**
  - เพิ่มการตรวจสอบและปฏิเสธการโหลดไฟล์เซฟที่มาจาก Schema เวอร์ชันที่ใหม่กว่า:
    ```javascript
    if (s.schemaVersion && s.schemaVersion > SIM.SAVE_SCHEMA_VERSION) {
      throw new Error('ไฟล์เซฟสร้างจาก Schema เวอร์ชันที่ใหม่กว่า (' + s.schemaVersion + ' > ' + SIM.SAVE_SCHEMA_VERSION + ') ไม่สามารถโหลดได้');
    }
    ```
