# 👥 สถาปัตยกรรมกำลังคนสองระดับ: แรงงานสายผลิตเชิงสถิติ และการเลื่อนขั้นสู่หัวหน้ากลุ่ม
## (Hierarchical Workforce Architecture: Aggregate Production Pool & Named Foreman Emergence)

> [!IMPORTANT]
> **สถานะเอกสาร:** พิมพ์เขียวสถาปัตยกรรมระบบกำลังพล (Workforce Architecture Specification)  
> ออกแบบมาเพื่อแก้ปัญหาคอขวดด้านประสิทธิภาพ (Performance Bottleneck) เมื่อบริษัทเติบโตสู่ระดับโรงงานขนาดใหญ่ที่มีพนักงานหลักร้อยหรือหลักพันคน โดยยังคงรักษาความมีชีวิตชีวาของจิตวิทยา NPC ผ่านระบบหัวหน้ากลุ่ม  
> **สำหรับ AI ที่จะลงมือโค้ด (Gemini):** ใช้เอกสารนี้เป็นข้อกำหนดในการออกแบบ `sim.js`, `data.js`, และการเรนเดอร์ภาพ 2D Canvas

## 1. ปรัชญาการออกแบบ: แก้ปัญหา Scalability ด้วยระบบสองระดับ (The Two-Tier Concept)

หากเกมต้องจำลองแกนมนุษย์ 14 บุคลิกภาพ, 18 ค่านิยม, 30 ความถนัด และ 12 สถานะชีพ ให้กับพนักงานทุกคนแบบ 1 ต่อ 1 เมื่อโรงงานขยายตัวถึง 500 – 1,000 คน CPU ของเบราว์เซอร์หรือมือถือจะคำนวณไม่ไหวและเกิดอาการเฟรมเรตตก (Lag)

เพื่อความสมดุลระหว่าง **ความลึกซึ้งของเกม (Depth)** และ **ประสิทธิภาพ 60 FPS (Performance)** ระบบจึงถูกแบ่งออกเป็น **2 ระดับ**:

```
┌────────────────────────────────────────────────────────────────────────┐
│ ระดับที่ 1: คีย์แมนและหัวหน้ากลุ่ม (Named NPCs with Human Core 1.0.0)    │
│ • มีตัวตน มีชื่อ มีหน้าตา Chibi เดินบนแผนที่ Campus                      │
│ • มีแกนมนุษย์ human-core.js ขับเคลื่อนจิตวิทยา 100%                    │
│ • ผู้บริหาร, ฝ่ายขาย, วิศวกร R&D, ผู้จัดการคลัง และ "หัวหน้าช่าง/โฟร์แมน" │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ คอยคุมและส่งออร่าบัฟ (Leadership Aura)
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ ระดับที่ 2: พนักงานฝ่ายผลิตทั่วไป (Statistical Workforce Pool)           │
│ • เป็น "ตัวเลขเชิงสถิติ (Aggregate Data Pool)" ไม่สร้าง Profile ทีละคน │
│ • รองรับคนงานได้ตั้งแต่ 10 คน จนถึง 1,000+ คน โดยกินทรัพยากร CPU คงที่   │
│ • คำนวณกำลังการผลิต ของเสีย และค่าจ้างรวมในระดับกลุ่ม                     │
│ • เมื่อมีคนงานผลงานเด่น สามารถ "เลื่อนขั้นกลายร่างเป็นหัวหน้ากลุ่ม" ได้!  │
└────────────────────────────────────────────────────────────────────────┘
```

## 2. โครงสร้างข้อมูลแรงงานฝ่ายผลิตทั่วไป (Statistical Workforce Pool)

ในโรงงานผลิต (Factory Plant) และคลังสินค้า กำลังคนระดับปฏิบัติการจะถูกจัดเก็บเป็นตัวแปรกลุ่มใน `w.workforce`:

```javascript
// โครงสร้างข้อมูลแรงงานสายผลิตใน sim state (กินหน่วยความจำน้อยมาก)
w.workforce = {
  assembly: {
    headcount: 45,            // จำนวนช่างประกอบในกะ (คน)
    experienceLevel: 42.5,     // ระดับทักษะเฉลี่ยรวม (0-100)
    morale: 75.0,              // ดัชนีขวัญกำลังใจรวม (0-100)
    fatigue: 15.0,             // ความเหนื่อยล้าสะสมรวม (0-100)
    baseDailyWage: 38000,      // อัตราค่าจ้างเฉลี่ยต่อหัว (380 บาท = 38,000 สตางค์)
    activeForemanId: "emp-4",  // รหัสหัวหน้ากลุ่มที่คุมไลน์นี้ (เชื่อมกับ Named NPC)
    shift: "day"               // กะการทำงาน (day = 08:30-17:00, night = 20:00-05:00)
  },
  qualityControl: {
    headcount: 8,
    experienceLevel: 58.0,
    morale: 80.0,
    fatigue: 10.0,
    baseDailyWage: 40000,
    activeForemanId: "emp-6",
    shift: "day"
  },
  logisticsCrew: {
    headcount: 12,
    experienceLevel: 35.0,
    morale: 70.0,
    fatigue: 20.0,
    baseDailyWage: 36000,
    activeForemanId: "emp-7",
    shift: "day"
  }
};
```

### 2.1 สูตรการคำนวณผลผลิตรวมของไลน์ (Aggregate Production Math)
กำลังการผลิตต่อชั่วโมงของไลน์ประกอบ คำนวณจากสูตรสถิติที่ไม่ต้องลูปทีละคน:

$$\text{OutputPerHour} = \text{headcount} \times \text{BaseRatePerWorker} \times \text{SkillFactor} \times \text{MoraleFactor} \times \text{ForemanBonus}$$

* **`BaseRatePerWorker`:** กำลังการผลิตฐานตามประเภทสินค้า (เช่น ประกอบลำโพงได้ 1.2 ชิ้น/ชั่วโมง/คน)
* **`ForemanBonus` (ออร่าหัวหน้ากลุ่ม):**
  * หากมีหัวหน้ากลุ่ม (Named Foreman) ยืนคุมอยู่ในโรงงาน ค่าความเป็นผู้นำ (`leadership`) และความรอบคอบ (`conscientiousness`) ของหัวหน้าจะช่วยเพิ่มผลผลิตขึ้น 15–30% และลดของเสียลงได้สูงสุด 40%!
  * หากไม่มีหัวหน้ากลุ่ม (หรือหัวหน้าป่วย/ไปพัก) ไลน์จะทำงานด้วยประสิทธิภาพฐาน 70%

### 2.2 การรับสมัครและปรับลดคนงานทั่วไป (Workforce Scaling)
* ฝ่ายบุคคล (HR Manager) ไม่ต้องสัมภาษณ์ทีละคน แต่สามารถเปิดรับสมัครเป็น **"ชุดกำลังคน (Labor Batches)"**:
  * เช่น รับช่างประกอบเพิ่ม +10 คน หรือ +50 คน เพื่อรองรับออเดอร์ล็อตใหญ่
  * เมื่อจบโปรเจกต์หรือช่วงโลว์ซีซั่น สามารถปรับลดขนาดกะได้ โดยจ่ายเงินชดเชยตามกฎหมายแรงงาน

## 3. ตัวตนของหัวหน้ากลุ่มและคีย์แมน (The Named Key Personnel)

เฉพาะตำแหน่งที่มีความสำคัญในการตัดสินใจเท่านั้น ที่จะถูกสร้างเป็น **Named NPC เต็มรูปแบบ** (มี Chibi บนแผนที่ และมีแกน `human-core.js`):

| บทบาท (`Role`) | ตำแหน่งในบริษัท | หน้าที่ในการขับเคลื่อนระบบ | การมีตัวตนบนแผนที่ Campus |
| :--- | :--- | :--- | :--- |
| `ceo` | ประธานบริษัท / ผู้ก่อตั้ง | บริหารทิศทาง วงเงินกู้ อนุมัติงบขยายโรงงาน | นั่งห้องผู้บริหารใน Office HQ |
| `sales_lead` | หัวหน้าฝ่ายขาย | เจรจา ปิดดีล รับออเดอร์ราคาสูงเข้าบริษัท | นั่งโต๊ะขาย โทรศัพท์ ออกไปพบลูกค้า |
| `production_foreman` | **หัวหน้าช่าง / โฟร์แมน** | **คุมสายการผลิต คุมคนงาน 50–100 คน** | **เดินตรวจโรงงาน ยืนคุมแท่นผลิตหลัก** |
| `qc_supervisor` | **หัวหน้าตรวจคุณภาพ** | **คุมมาตรฐาน QC และตัดสินใจปล่อยล็อตสินค้า** | **ส่องกล้องตรวจงาน และเซ็นอนุมัติผ่าน QC** |
| `warehouse_manager`| ผู้จัดการคลังสินค้า | คุมสต็อกชิ้นส่วน ตรวจรับสินค้าที่ Loading Dock | ยืนคุมประตูคลังสินค้าและจุดถ่ายของ |
| `rnd_engineer` | วิศวกรวิจัยและพัฒนา | วิจัยแบบแปลนสินค้าใหม่ (T1 ➔ T5) | นั่งในอาคารแล็บ R&D |
| `hr_admin` | ผู้จัดการฝ่ายบุคคล/บัญชี | คำนวณเงินเดือน และเปิดรับคนงานเข้าสายผลิต | นั่งโต๊ะบัญชีใน Office HQ |

## 4. กลไกการเลื่อนขั้น: กำเนิดตัวตนจากคนงานนิรนาม (The Emergence Engine)

นี่คือจุดเด่นที่ทำให้เกมมีความผูกพันและอบอุ่นใจ: **"คนงานธรรมดา สามารถก้าวขึ้นมามีตัวตนในเกมได้"**

```
┌────────────────────────────────────────────────────────────────────────┐
│ [เหตุการณ์จุดชนวน: Trigger Event]                                       │
│ • โรงงานขยายสายผลิตใหม่ ต้องการหัวหน้าช่างเพิ่ม                            │
│ • หรือ หัวหน้าช่างคนเดิม ลาออก / เลื่อนตำแหน่ง / เกษียณ                   │
│ • หรือ มีคนงานในไลน์สร้างสถิติประกอบงานดีเด่นในรอบ 90 วัน                 │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ ระบบสุ่มคัดเลือกคนงานเด่น 1 คนจาก Pool
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ [กระบวนการกำเนิดตัวตน: Materialization & Promotion]                     │
│ 1. ลดตัวเลข headcount ใน Pool ลง 1 คน                                    │
│ 2. ระบบสุ่มชื่อภาษาไทย (เช่น "ช่างสมศักดิ์", "หัวหน้าวิชัย")                │
│ 3. กำเนิดแกนมนุษย์ H.createProfile() ที่มี Dexterity และ Leadership สูง  │
│ 4. Spawn โมเดลตัวละคร Chibi ปรากฏตัวขึ้นในโรงงานพร้อมไอคอนเลื่อนขั้น 🎖️    │
│ 5. ผู้เล่นคลิกดู Character Sheet ประวัติความเป็นมาได้ทันที!               │
└────────────────────────────────────────────────────────────────────────┘
```

### 4.1 เรื่องราวเบื้องหลังของหัวหน้าคนใหม่ (Procedural Backstory)
เมื่อเลื่อนขั้น ระบบจะสร้างประวัติย่อแบบสุ่มที่น่าประทับใจ:
* *"ช่างสมศักดิ์ — อดีตคนงานไลน์ประกอบที่ทำงานอย่างเงียบ ๆ มานาน 6 เดือน ได้รับการยอมรับจากเพื่อนร่วมงานจนได้รับเลือกเป็นโฟร์แมนคนใหม่"*
* พนักงานคนนี้จะมีค่าความภักดีต่อบริษัท (`morale` เริ่มต้นสูงถึง 90) และภูมิใจในตำแหน่งใหม่มาก

## 5. การแสดงผลบนหน้าจอ 2D Canvas (Visual Representation)

แม้คนงานในไลน์จะเป็นตัวเลข แต่หน้าจอ 2D Canvas จะยังคงดูมีชีวิตชีวาและไม่เงียบเหงา:
1. **ภาพภายนอกอาคารโรงงาน (Factory Exterior):**
   * มีตัวเลขอินดิเคเตอร์เล็ก ๆ เหนือหลังคาโรงงาน: แสดง `👷‍♂️ 45 คน | ประสิทธิภาพ 94%`
   * ในช่วงพักเที่ยง (12:00 น.): Canvas จะแสดง **กลุ่มคนงาน Chibi นิรนาม** (Silhouette หรือ Sprite ช่างใส่หมวกเซฟตี้) เดินเป็นกลุ่ม 5–10 คน ออกจากโรงงานข้ามลานไปกินข้าวที่โรงอาหาร สร้างบรรยากาศโรงงานที่คึกคักสมจริง
2. **ตัวละครหัวหน้ากลุ่ม (Named Foreman):**
   * เดินเด่นชัด มีป้ายชื่อภาษาไทย มีบอลลูนสั่งงาน 🗣️ หรือไอคอนตรวจงาน 📋 เหนือหัว
   * ผู้เล่นสามารถคลิกที่ตัวหัวหน้ากลุ่ม เพื่อดูว่า *"ตอนนี้กำลังคุมคนงานอยู่กี่คน ลูกน้องมีปัญหาอะไรไหม"* ได้ทันที!
