# แกนมนุษย์กับธุรกิจในอนาคต — หลักฐานและคำตัดสิน

ตรวจแหล่งข้อมูลจริงทางอินเทอร์เน็ตวันที่ **10 พฤศจิกายน 2026** เพื่อประกอบการตรวจรับ core `1.0.0` ผู้ใช้มอบหมายให้ Codex ตัดสินใจ ไม่ได้กำหนดให้สร้างกิจการทุกชนิดในแพตช์นี้

## ข้อสรุปสำหรับการออกแบบ

ใช้ความสามารถทั่วไป **30 ด้าน** ประกอบเป็นทักษะที่เรียนรู้ได้ โดยมีบุคลิก **14** ค่านิยม **18** และสภาพเปลี่ยนได้ **12** มิติ ธุรกิจใหม่เพิ่มความรู้ ทักษะ กระบวนการ เครื่องมือ เงื่อนไขและเนื้อหาภายนอกแกน ไม่เพิ่มแกนชื่อ “เก่งอวกาศ” หรือ “เก่งหุ้น” การเพิ่มจำนวนมิติอย่างเดียวไม่ใช่หลักฐานว่าคนสมจริง จึงตรวจด้วยการเปลี่ยนค่าทีละด้านและลองให้ทักษะใหม่ทำงานจริงด้วย

นี่คือแบบจำลองสำหรับเกม ไม่ใช่แบบวัดทางจิตวิทยาหรือการรับรองว่าครบมนุษย์ทุกแง่มุมตลอดไป จุดที่รับรองด้วยโครงสร้างได้คือธุรกิจตัวอย่างด้านล่างเพิ่มผ่านสัญญาเดิมได้ และไม่ต้องเปลี่ยนสูตรหรือสุ่มบุคลิกของคนเดิมใหม่

## ช่องว่างที่แก้ก่อนล็อก

- `analytical` กว้างเกินไปที่จะบอกความเข้าใจภาษา คิดตัวเลข สังเกตความผิดปกติ และให้เหตุผลเมื่อข้อมูลไม่แน่นอน จึงแยก `verbal`, `numerical`, `problemSensitivity`, `uncertaintyReasoning`
- `sensory` ตัวเดียวทำให้การฟังเสียงเครื่องยนต์ อ่านแผงควบคุม แยกสี และชิมอาหารเหมือนกันเกินไป จึงแยก `visualAcuity`, `colorDiscrimination`, `hearing`, `speechClarity`, `tasteSmell` และ `perceptualSpeed`; คง `sensory` สำหรับการผสานการรับรู้/งานละเอียดที่ยังไม่ได้แยกโมดาลิตี
- การขับยานหรือเครื่องจักรไม่ใช่พละกำลัง/มือคล่องอย่างเดียว เพิ่ม `attention`, `reactionSpeed`, `controlPrecision`, `coordination`, `balance`, `flexibility`
- ความสามารถใหม่ 16 ด้านรวมกับของเดิม 14 เป็น 30; `tasteSmell` และ `uncertaintyReasoning` เป็นการแยกเพื่อเกม ไม่ใช่การอ้างว่าเป็นชื่อมาตรวัด O*NET โดยตรง
- เพิ่ม `humility` กับ `optimism` เพราะความถ่อมตน/แนวโน้มคาดหวังผลบวกต่างจากซื่อตรง/ทนเครียด เพิ่มค่านิยม `care`, `stewardship`, `influence`, `tradition`, `variety`, `craftsmanship` ให้เหตุผลเรื่องดูแลสัตว์ สิ่งแวดล้อม อำนาจ วัฒนธรรม ความแปลกใหม่และฝีมือมีที่อยู่ชัดเจน
- ภาวะบาดเจ็บ อายุ อุปกรณ์ช่วยและสภาพแวดล้อมเป็นความสามารถขณะนั้น ไม่เขียนทับ intrinsic profile ใช้ performance context และระบบสถานะ/อุปกรณ์ภายนอก

## ตารางลองกับกิจการในอนาคต

ตารางนี้เป็น **ข้อเสนอการประกอบโมดูล** ไม่ใช่ประกาศว่าเกมเปิดกิจการเหล่านี้ได้แล้ว น้ำหนักตัวเลขใน `CompanyData.INDUSTRY_SKILL_TEMPLATES` เป็นจุดตั้งต้นเพื่อทดสอบ ไม่ใช่สัดส่วนความสำคัญที่วัดจากงานวิจัย

| ธุรกิจ/งาน | ความสามารถที่ประกอบได้ | ความรู้/ระบบที่ต้องเพิ่มภายนอกแกน |
| --- | --- | --- |
| อวกาศและดาวเทียม | วิเคราะห์ ตัวเลข มิติสัมพันธ์ เห็นปัญหา สมาธิ สงบในวิกฤต | กลศาสตร์วงโคจร อิเล็กทรอนิกส์ ใบรับรอง ภารกิจ ความน่าเชื่อถือและความเสียหาย ไม่ใช่ส่งสินค้าโรงงานเดิมแล้วเรียกว่าจรวด |
| ยานยนต์/EV | วิเคราะห์ เห็นปัญหา มองรายละเอียด คล่องมือ ฟังเสียง | เครื่องยนต์ แบตเตอรี่ วินิจฉัยอาการ อะไหล่ ความปลอดภัยและการทดสอบ |
| ขับรถ/ควบคุมยาน | ควบคุมแม่นยำ ตอบสนอง ประสานร่างกาย มิติสัมพันธ์ สมาธิ | ใบอนุญาต เส้นทาง เชื้อเพลิง สภาพอากาศ อุบัติเหตุและเครื่องช่วย |
| ก่อสร้าง/สถาปัตย์ | มิติสัมพันธ์ ตัวเลข กำลัง อึด ทรงตัว ยืดหยุ่น | แบบ วัสดุ กฎหมายอาคาร ขั้นงาน/โครงการ ผู้รับเหมา เครื่องจักรและการตรวจรับ |
| หุ้น/กองทุน/การลงทุน | ตัวเลข ให้เหตุผลภายใต้ความไม่แน่นอน วิเคราะห์ สังเกตปัญหา | ความรู้บัญชี/พอร์ต ข้อมูลตลาด ค่าธรรมเนียม สภาพคล่อง ความเสี่ยง เหตุการณ์ภายนอก ความเก่งไม่รับประกันกำไร; `riskTaking` เป็นนิสัยไม่ใช่ความเก่ง |
| สัตว์เลี้ยง/ฟาร์ม/สัตวแพทย์ | สังเกต เข้าใจอารมณ์/สัญญาณ วิเคราะห์ จำ คล่องมือ | ความรู้ตามชนิดสัตว์ สัญญาณพฤติกรรม สุขภาพ อาหาร ยา สวัสดิภาพและใบอนุญาต; ไม่ให้ emotionalInsight แปลว่าอ่านใจสัตว์ได้เอง |
| อาหาร/ร้านอาหาร | รสกลิ่น แยกสี คล่องมือ จัดระบบ เห็นปัญหา | สูตรอาหาร โภชนาการ สต็อกเน่าเสีย สารก่อแพ้ สุขอนามัย บริการและความต้องการลูกค้า |
| เกษตร/ชีวภาพ | สังเกต วิเคราะห์ จัดระบบ อึด การเรียนรู้ | สายพันธุ์ ดิน น้ำ โรค ฤดูกาล วงจรเติบโตและผลผลิต |
| ซอฟต์แวร์/AI/ไซเบอร์ | วิเคราะห์ จำ เรียนรู้ เห็นปัญหา สมาธิ | ภาษาโปรแกรม ระบบข้อมูล การทดสอบ การออกแบบและวงจรผลิตภัณฑ์ |
| การแพทย์/ห้องทดลอง | จำ วิเคราะห์ แม่นยำ คล่องมือ เห็นปัญหา | การศึกษา การวินิจฉัย อุปกรณ์ ใบอนุญาต คนไข้ การยินยอมและความเสี่ยง |
| กฎหมาย/บัญชี | เข้าใจภาษา วิเคราะห์ ตัวเลข จำ ละเอียด | กฎหมายตามเขตเวลา/ประเทศ มาตรฐานบัญชี คดี ภาษีและเอกสาร |
| การศึกษา/ที่ปรึกษา | เข้าใจภาษา สื่อสาร เข้าใจอารมณ์ ออกเสียงชัด จัดระบบ | ความรู้วิชา วิธีสอน ผู้เรียนและการประเมินผล; ความสำเร็จผู้เรียนไม่เท่าความเก่งผู้สอนเพียงคนเดียว |
| ศิลปะ/เกม/ดนตรี/สื่อ | สร้างสรรค์ สี เสียง สื่อสาร มิติสัมพันธ์ | เครื่องมือ สไตล์ ความรู้ศิลป์ ผู้ชม ลิขสิทธิ์และช่องทางขาย |
| โลจิสติกส์/พลังงาน | จัดระบบ ตัวเลข มิติสัมพันธ์ สมาธิ ควบคุมแม่นยำ | เครือข่าย การซ่อม ระบบสาธารณูปโภค ความต้องการ เวลาและกฎความปลอดภัย |
| โรงแรม/ท่องเที่ยว/งานดูแล | สื่อสาร เข้าใจภาษา/อารมณ์ จัดระบบ อึด | ภาษาเฉพาะ พื้นที่ การจอง บริการ ฤดูกาลและความต้องการผู้รับบริการ |
| ธุรกิจที่ยังนึกไม่ออก | สร้าง skill spec จากความสามารถทั่วไป เลือกแรงจูงใจและภาระงาน | ถ้าต้องมีฟิสิกส์ ตลาด สิ่งมีชีวิตหรือเงื่อนไขใหม่ ให้เพิ่มระบบนั้นพร้อม save validation และเทสต์ของมัน; ไม่ฝืนเรียก generic service ว่าระบบเฉพาะที่เสร็จแล้ว |

## สัญญาที่ทำให้ต่อยอดได้

1. เพิ่ม skill ผ่าน `Data.registerSkill`/`Sim.addSkill` โดยกำหนด aptitude weights; การฝึก/ประสบการณ์อยู่ใน skill record คนเดิมและทักษะเดิมไม่ถูกสุ่มใหม่
2. เพิ่ม role, material, product และ task kind ผ่าน registry; งานเฉพาะระบุ `domain`, `workload`, `hazard`, `complexity`, แรงจูงใจและผลตอบแทนแบบข้อมูลได้ มีการตรวจขอบเขตและ save/load
3. เพิ่มทางเลือกการกระทำผ่าน `scoreOptions`: ใช้ค่านิยม/ความต้องการ/นิสัยร่วมกับ skill fit, memory, effort และ delay ห้ามให้ “คนชอบเสี่ยง” กลายเป็น “คนคำนวณเก่ง” โดยอัตโนมัติ
4. เพิ่มเป้าหมายชีวิตและราคาใน `catalog.lifeGoals` → `deriveAspirations(context.goalSpecs)` เพิ่มเหตุการณ์ผ่าน `evaluateLifeEvent` แบบ deltas/ตัวจัดการภายนอก บ้าน รถ การแต่งงานไม่ใช่รายชื่ออนาคตที่ถูกจำกัดไว้ตลอดไป
5. ความเชื่อ รสนิยม วัฒนธรรม ความทรงจำ อัตลักษณ์ ครอบครัว ความสัมพันธ์ สภาพร่างกายเฉพาะและใบอนุญาตอยู่ในโมดูล/ข้อมูลแยกของ simulation ใช้คะแนนแกนประกอบ ไม่เพิ่ม trait ใหม่ทุกครั้งที่มีเนื้อเรื่องใหม่ และต้องเพิ่ม validation ของข้อมูลใหม่ใน save ตามจริง

## สิ่งที่ยังไม่อ้างว่าพิสูจน์แล้ว

ทดสอบรองรับทักษะ/งานข้ามธุรกิจและการคงสัญญาข้อมูล ไม่ใช่ทดสอบระบบลงทุน/อวกาศ/อาหาร/สัตว์จริงที่ยังไม่มี การกระจายค่าบุคลิกใช้ deterministic sampling สำหรับเกม ยังไม่ปรับเทียบกับประชากรจริง ความสัมพันธ์/อารมณ์เป็นแบบจำลองย่อ ผู้พัฒนายังต้องเล่นทดสอบความหลากหลายและเหตุผลของคนเมื่อเพิ่มระบบใหม่ เครื่องมือและสิ่งอำนวยความสะดวกช่วยผลการทำงานได้ แต่ไม่ได้มอบความรู้/ใบอนุญาตหรือยืนยันความเหมาะสมของบุคคลจากคะแนนเดียว
