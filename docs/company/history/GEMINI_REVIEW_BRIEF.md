# งานปัจจุบันสำหรับ Gemini Argon4 — ตรวจและพัฒนาแกนมนุษย์/โครงสร้าง

ผู้ใช้ให้ความสำคัญกับแกนนิสัยและความสามารถมากที่สุด ต้องการใช้แกนเดิมต่อระยะยาวโดยล็อกถาวรหลังตรวจรับ ผู้ใช้กำหนดให้คุณตรวจและพัฒนาต่อจาก Codex แล้วส่งกลับให้ Codex ตรวจอีกครั้ง ก่อนให้ Claude ทำกราฟิก

## เป้าหมาย

ตรวจอย่างอิสระ คิดเองและตัดสินใจเองในขอบเขตนี้ อย่ายึดจำนวนมิติ สูตร หรือแผนจาก Codex/Opus ว่าถูกต้องแล้ว การทดสอบผ่านเพียงยืนยันกรณีที่ตรวจ ไม่พิสูจน์ว่าแบบจำลองมนุษย์ครบทุกอนาคต ต้องประเมินทั้งโครงสร้าง สูตรและพฤติกรรมจริง แล้วแก้ส่วนที่บกพร่องหรือขาดตามเหตุผล

อ่าน AGENTS, สกิล company-foundation, สถานะโครงการ, HUMAN_CORE_MODEL และซอร์สที่เกี่ยวข้องก่อนเปลี่ยน ตรวจ baseline และผลทดสอบเดิมด้วยตัวเอง ถ้าข้อมูลสรุปขัดกับซอร์สให้ตรวจหลักฐานและแก้เอกสารให้ตรง

## ขอบเขตที่ต้องตรวจ

- ความหมายและความซ้ำซ้อนของบุคลิก 9 มิติ ค่านิยม 9 มิติ ความถนัด/ศักยภาพ 10 ด้าน: มีช่องว่างพื้นฐานใดที่อนาคตต้องใช้และเพิ่มผ่านส่วนขยายอย่างถูกต้องไม่ได้หรือไม่ ประเมินจำนวนใหม่ได้ ไม่ต้องเพิ่มเพียงเพื่อให้ดูเยอะ
- แยก innate baseline, ความเชี่ยวชาญที่ฝึกได้ ประสบการณ์ สภาพชีวิต ความเชื่อ/ความทรงจำ/ความสัมพันธ์ และบริบทให้เหมาะสม อธิบายสิ่งที่อยู่ในแกนกับระบบภายนอก โดยไม่ hardcode อาชีพหรือสถานการณ์ทั้งหมดลงแกน
- รูปแบบศักยภาพ/เพดานทักษะ การเรียนรู้ การเสื่อม/ฟื้นสภาพ อารมณ์ ความต้องการ ค่านิยมและแรงจูงใจ: อะไรจำเป็นต้องเป็นฐานก่อนล็อก อะไรเป็นส่วนขยาย อย่าถือว่าทุกค่าที่ประกาศมีผลจริงโดยยังไม่ไล่ผู้ใช้ข้อมูล
- ตรวจสูตร ability, quality, scoreOptions, respondToRequest, workplaceVoice และสภาพชีวิตด้วยกรณีตัวละคร/สถานการณ์ที่ต่างกัน ตรวจผลสุดขอบ การทบซ้อนค่าปรับ ความสัมพันธ์ที่สมเหตุสมผล การหลีกเลี่ยง stereotype และเหตุผลที่แสดงให้ผู้ใช้เข้าใจได้
- ตรวจความเป็นอิสระของ NPC: การเลือกงาน พัก กิน เรียนรู้ ช่วยเพื่อน ตอบรับ/ต่อรอง/ปฏิเสธ OT แจ้งข้อกังวลและลาออก มีเหตุผลจริงหรือแค่ชื่อฟังก์ชัน ทดสอบสิ่งที่ยังไม่ครอบคลุมโดยเพิ่มกรณีที่มีความหมาย
- ทดลองเพิ่มอาชีพ/ทักษะ/สินค้าและตัวเลือกพฤติกรรมใหม่ภายนอกแกน ดูว่าไม่ทำให้ seed เก่า ทักษะเดิม หรือเซฟเสีย API ไหนยังผูกกับเกม/โรงงานชนิดเดียวเกินไปให้ปรับ
- ตรวจงานสองโซน การจอง/คืน/ใช้วัตถุดิบ งานค้าง/ยกเลิก ซ่อม/ของเสีย เงินมัดจำ/ส่งมอบ/ใบแจ้งหนี้/รับเงิน ค่าแรง/หนี้/เงินค้าง การขยายพื้นที่ และเหตุผลจากคนย้อนมากระทบงาน/บริษัท
- ตรวจ invalid commands/save/load, malformed IDs/counters, reference integrity, replay, deterministic continuation, view purity และเวลาจำลองแยกเวลาวาด

## ทำได้และยังไม่ควรทำ

แก้แกนและโครงสร้างได้ในรอบตรวจนี้ เพราะยังไม่ล็อกถาวร ให้บันทึกเหตุผล ผลกระทบ และเพิ่ม/ปรับทดสอบตามพฤติกรรมที่ควรเป็น ไม่แก้ assertions เพื่อปิดบั๊ก หากเปลี่ยน core/save contract ให้กำหนดเวอร์ชันและ migration หรือระบุชัดว่าเซฟฉบับ review เดิมใช้ไม่ได้ พร้อมคำอธิบายตอนโหลด

`CORE_REVIEW_BASELINE.json` เป็นเพียงหลักฐานเทียบฉบับตรวจ ไม่ใช่ permanent lock หลังแก้และทดสอบแล้วจึงปรับด้วย `node tools/core-review.cjs --refresh-review` พร้อมรายงานว่าเปลี่ยนอะไร รัน check อีกครั้ง **ยังไม่สร้าง CORE_LOCK.json สถานะถาวร** และไม่อ้างว่าผู้ใช้ตรวจรับแล้ว

งานนี้เน้นแกน/โครงสร้าง ไม่ต้องออกแบบภาพ ตัวละครหรือ UI ฉบับสุดท้าย หน้า debug เปลี่ยนได้เท่าที่จำเป็นต่อการตรวจระบบ ต้องรักษาขอบเขต simulation กับ presentation ให้ Claude รับช่วงได้
