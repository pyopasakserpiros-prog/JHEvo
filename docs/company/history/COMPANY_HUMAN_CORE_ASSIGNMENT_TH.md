# ใบสั่งงานแรก: เกมบริษัทเวอร์ชันแรกที่เล่นได้ และแกนมนุษย์

**สถานะ: พร้อมให้ AGY / Opus ดำเนินงาน — ยังไม่ได้พัฒนา**
**ฐาน:** สาขา `company`, concept `COMPANY_SIMULATION_CONCEPT_AND_ARCHITECTURE.md`
**เป้าหมาย:** สร้างเกมบริษัทเวอร์ชันแรกที่เล่นได้จริง พร้อมตัวละครและวงจรบริษัท โดยออกแบบแกนบุคลิก ค่านิยม ความสามารถและศักยภาพเป็นรากฐาน แล้วล็อกแกนหลังตรวจรับ ให้ระบบอื่นขยายผ่านข้อมูลและส่วนเชื่อมต่อได้

## ก่อนลงมือ

อ่าน `AGENTS.md`, สกิลเฉพาะโครงการที่เกี่ยวข้อง, `project_status_and_ai_onboarding.md`, concept บริษัท และซอร์ส/ทดสอบ JS2 ที่เกี่ยวข้องกับ human core, NPC, การตัดสินใจและ save ตรวจสาขาและงานที่เปลี่ยนล่าสุดก่อนเริ่ม รักษางานของผู้อื่น ผู้ใช้มอบดุลพินิจให้คิดและตัดสินใจในขอบเขตงานนี้ ไม่จำเป็นต้องคัดลอกข้อเสนอทั้งหมดจากเอกสาร concept

ผู้ใช้ต้องการสร้างฐานบุคลิกและความสามารถให้ครบองค์ประกอบพื้นฐานก่อนพัฒนาระบบบริษัทอื่น ๆ คำว่า **ครบ** หมายถึงโครงสร้างมนุษย์พื้นฐานที่พิจารณาอย่างรอบด้าน รองรับคนหลากหลายอาชีพและขยายได้ ไม่ใช่รับประกันว่าจำลองมนุษย์ได้ทุกกรณีอย่างสมบูรณ์ อธิบายขอบเขตและสิ่งที่ยังไม่ยืนยันตามจริง

## ออกแบบแกน

1. ตรวจสอบ `GAME_SOURCE/js/human_core.js` และระบบ JS2 จริง: แยกสิ่งที่ยืมแนวคิดหรือใช้ซ้ำได้ ส่วนที่ผูกกับโลกเทพเซียน และเหตุผลที่ควรสร้างใหม่ **รักษาแกน JS2 เดิม** และสร้างแกนเกมบริษัทแยกชัดเจน พิจารณา `COMPANY_SOURCE/` ในสาขานี้ตามความเหมาะสม
2. ออกแบบบุคลิกเป็นมิติที่ผสมกันได้ เช่น การเข้าสังคม ความรอบคอบ การร่วมมือ ความเปิดรับ ความกล้าเสี่ยง และการตอบสนองต่อแรงกดดัน ไม่บังคับคนไว้ใน archetype ตายตัว พิจารณาจำนวนมิติที่จำเป็นจริงและความซ้ำซ้อน
3. ออกแบบค่านิยม แรงจูงใจ ความต้องการและเป้าหมาย เช่น ความมั่นคง รายได้ อิสระ ความยุติธรรม ความสัมพันธ์ การเรียนรู้ การเติบโต และความหมายของงาน ให้คนที่มีความสามารถใกล้กันเลือกต่างกันได้ตามบริบท
4. แยก **ความถนัดพื้นฐาน / ศักยภาพการเรียนรู้ / ทักษะที่ฝึกได้ / ประสบการณ์ / ผลงานจริง** ให้ชัด พิจารณาการวิเคราะห์ ความคิดสร้างสรรค์ การสื่อสาร การจัดการ ความละเอียด การประสานงาน และความสามารถอื่นตามเหตุผล รองรับลูกค้า ผู้บริหาร พนักงานและอาชีพนอกบริษัทซอฟต์แวร์ โดยให้ทักษะอาชีพใหม่เพิ่มนอกแกนได้
5. แยกคุณลักษณะค่อนข้างคงที่ออกจากสภาพเปลี่ยนได้ เช่น สุขภาพ พลังงาน สมาธิ ความเครียด ความมั่นใจ ภาระชีวิต และความต้องการพัก ออกแบบให้สถานการณ์และประสบการณ์มีผลตามเหตุผล ไม่ตีตราว่าคนกลับตรงเวลาเป็นคนขี้เกียจ หรืออนุมานผลงานจากคุณสมบัติเพียงข้อเดียว
6. ออกแบบจุดเชื่อมต่อให้ความสัมพันธ์ ความไว้วางใจ ความขัดแย้ง ความเป็นธรรม วัฒนธรรมองค์กร ภาระงานและโอกาสภายนอก มีผลต่อทางเลือกได้ โดยพนักงานยังมีความเป็นตัวเองและสิทธิ์ตอบรับ ต่อรอง ขอความช่วยเหลือ พัก ปฏิเสธหรือออกจากงานตามเหตุผล
7. สำหรับแต่ละองค์ประกอบกำหนดความหมาย ช่วงค่า ค่าเริ่มต้น ความสัมพันธ์ ขอบเขตและวิธีจัดการค่าผิด/ข้อมูลขาด พร้อมตัวอย่างตัวละครหลายแบบ อธิบายว่าข้อมูลใดเก็บในแกน ใดเป็นสถานะ และใดอยู่ในระบบส่วนขยาย

## การล็อกแกนและความเข้ากันได้

- หลังพัฒนาและตรวจรับเสร็จ ให้ระบุชื่อไฟล์และขอบเขตแกนที่ล็อกอย่างชัดเจนในเอกสารและคำแนะนำ AI กำหนดเวอร์ชันแกนและ fingerprint หรือการตรวจความเปลี่ยนแปลง พร้อมวิธีตรวจที่ทำซ้ำได้
- **แพตช์ต่อไปห้ามแก้แกนที่ล็อกโดยพลการ** ส่วนขยาย/ทักษะ/อาชีพ/สถานการณ์สามารถเพิ่มภายนอกตามสัญญาเชื่อมต่อที่จัดเตรียมไว้
- ถ้ามีเหตุจำเป็นต้องแก้แกนหลังล็อก รวมถึงบั๊กร้ายแรง ให้บันทึกเหตุผล ผลกระทบต่อข้อมูลเก่า แผน migration และวิธีทดสอบ แล้วขอคำสั่งหรืออนุมัติจากผู้ใช้ก่อนแก้แกนที่ล็อก กติกานี้ไม่ห้ามแก้ระหว่างสร้างแกนแพตช์แรกก่อนตรวจรับ
- ออกแบบการสร้างตัวละครจาก seed ให้ทำซ้ำได้ ระบุการเก็บ seed/เวอร์ชันที่จำเป็น และวิธีบันทึก/โหลดที่รองรับการเพิ่มข้อมูลภายนอกในอนาคต อย่าสัญญาความเข้ากันได้เกินกว่าที่ทดสอบ

## เกมเวอร์ชันแรกที่เล่นได้

ผู้ใช้ต้องการ **เกมที่เล่นได้ตั้งแต่แพตช์นี้** ไม่ใช่ส่งเพียงแกนหรือเอกสาร ออกแบบขอบเขตที่ทำสำเร็จได้จริงด้วยตนเอง โดยให้มีอย่างน้อย:

- เริ่มเกมใหม่ บริหารบริษัทที่มีเงินจำกัด มีเวลาเดิน/หยุด/ปรับความเร็ว เลือกดูตัวละครและสถานะบริษัท มีเป้าหมายและเงื่อนไขความสำเร็จ/วิกฤตที่ชัดเจน และบันทึก/โหลดต่อได้
- พื้นที่บริษัทมีทั้ง **โซนออฟฟิศและโซนโรงงาน** ที่มองเห็นได้ตั้งแต่เวอร์ชันแรก พร้อมสถานีทำงานที่ใช้ได้จริงทั้งสองโซน เช่น งานจัดการ/ขาย/วางแผนเชื่อมกับการผลิตสินค้าหนึ่งประเภท การรับคำสั่งซื้อ การจัดหาวัตถุดิบ ผลิต ตรวจ/ส่งมอบ รับเงิน จ่ายค่าแรงและค่าใช้จ่าย วางให้ข้อมูลแต่ละขั้นเชื่อมกันและไม่มีวัตถุดิบหรือเงินเกิดขึ้นฟรี
- ผู้เล่นกำหนดนโยบาย ลำดับความสำคัญ งานหรือการจัดสรรทรัพยากรได้ พนักงานตัดสินใจและลงมือทำตามงานที่มี ความถนัด สภาพและบริบท มี feedback ว่ากำลังทำอะไร เหตุใดจึงรอ และปัญหากระทบอะไร ผู้เล่นเข้าใจวิธีแก้
- สร้าง **ภาพ/โมเดลตัวละครที่มองเห็นได้จริงในเกม** เหมาะกับสไตล์และเทคโนโลยีที่เลือก มีตัวละครหลายคนที่แยกแยะกันได้ และสื่ออย่างน้อยการเดิน ทำงาน และพัก เลือก 2D sprites หรือโมเดลที่เหมาะกับเครื่องมือและประสิทธิภาพ ไม่บังคับ 3D หรืออ้างว่ามีภาพที่ยังไม่ได้สร้าง หากใช้ภาพภายนอกให้ตรวจสิทธิ์และรวม asset ที่จำเป็นในเกม
- ออกแบบพื้นที่ สถานี เครื่องจักร สินค้าและงานเป็นข้อมูลที่ขยายได้ เพื่อรองรับการเพิ่มห้อง โซน อาคาร สายผลิต อาชีพและธุรกิจในอนาคต โดยไม่ต้องเขียนระบบใหม่ทั้งหมด เวอร์ชันแรกต้องแสดงสองโซนและใช้งานจริง; ระบบก่อสร้าง/ซื้อที่ดินแบบสมบูรณ์ให้ทำตามความเหมาะสมและระบุส่วนที่ยังไม่มี
- เลือกขนาดทีม ความหลากหลายสินค้า ภาพ และความลึกของเศรษฐกิจตามความสามารถในแพตช์เดียว ให้เส้นทางเล่นหลักครบก่อนขยายฟีเจอร์ ไม่จำเป็นต้องทำทุกอุตสาหกรรม นักลงทุน หรือเหตุการณ์ทั้งหมดใน concept
- รองรับหน้าจอมือถือและเดสก์ท็อป เล่นออฟไลน์ได้ตามแนวทางโครงการ พร้อมวิธีเปิดเกมชัดเจน และเก็บ JS2 แยกจากเกมใหม่

## ตรวจรับและส่งมอบ

ตรวจแกนมนุษย์ตามเกณฑ์ข้างต้น รวมการสร้างซ้ำจาก seed ความหลากหลาย ค่าไม่ถูกต้อง การบันทึก/โหลด ส่วนขยายและการตรวจจับการแก้แกน ตรวจการเล่นทั้งวงจรตั้งแต่เริ่มบริษัท รับงาน จัดหา ผลิต ส่งมอบ จ่ายค่าใช้จ่าย จนถึงความสำเร็จหรือวิกฤต ตรวจคนทำงานข้ามโซน คอขวด วัตถุดิบหมด เงินไม่พอ UI มือถือ/เดสก์ท็อป ตัวละครแสดงจริง ประสิทธิภาพ และความเข้ากันได้ของเซฟ รายงานคำสั่ง ผลจริง และสิ่งที่ยังไม่ครอบคลุม

อัปเดต project status, สกิลและเอกสารที่เกี่ยวข้อง คู่มือเล่นและใช้แกน สถานะการล็อก ข้อจำกัด รายงานการส่งมอบ และ `START_HERE_FOR_AI.md` หลังเสร็จ แยกสิ่งที่ใช้ได้จริงออกจากข้อเสนออนาคต บันทึกขั้นตอนถัดไปให้ AI อื่นรับช่วงได้ ตรวจ git diff และสาขาเป้าหมายก่อนส่งมอบ รักษางานผู้อื่นและไม่ force push
