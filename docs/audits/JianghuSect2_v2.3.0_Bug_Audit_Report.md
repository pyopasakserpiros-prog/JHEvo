### N-01 (M) 🔎✅ เชลยศึกที่ถูกชักชวนเป็นศิษย์ ได้ "วิถี" ใหม่ แต่สายย่อย/คาถา/วิชาเป็นของวิถีเดิม
- **ไฟล์:** `js/sect.js` บรรทัด 6965–6971 (`SECT.handleDungeonPrisoner`, กรณี `RECRUIT_DEFECTOR`/`RECRUIT`)
- **โค้ด:**
  ```js
  const newNpc = g.SIM.addNpc(W, { ageYears: 24 + pris.stage * 3, quality: 0.85, rank: ..., stage: pris.stage });
  ...
  if (newNpc && newNpc.cult && CULT.PATHS[pris.path]) { newNpc.cult.path = pris.path; }
  ```
- **ปัญหา:** เขียนทับเฉพาะ `cult.path` โดยไม่คำนวณ `sub`, `mantra`, `techs`, `track` และ gauge ของวิถีใหม่ NPC จึงถือสายย่อย/คัมภีร์ปราณ/วิชาของวิถีที่สุ่มมาแต่แรก ทั้งที่ประกาศตัวเป็นวิถีของเชลย (ตรวจพบจากวิชา ยังไม่ได้ยืนยัน mantra)
- **หลักฐานจากการจำลอง:** `n82_150` (วันที่ 378, ขั้น 7, `renegadeOrigin` มีค่า) สร้างจากฟังก์ชันนี้ (จับสแต็กตอน `W.npcs.push` ได้ `SECT.handleDungeonPrisoner → SIM.addNpc`) ตอนเกิดมี `path: XIAN`, `sub: NONE` และวิชา **7 ตัว ซึ่ง 6 ตัวเป็นของวิถีอื่น** (BEAST_SOVEREIGN, DIVINE_CHANNELER, WANDERING_DAO, KARMA_SAMSARA, PRIMORDIAL_CHAOS, INK_LITERATI) ขณะที่ผู้บ่มเพาะทั้ง 24 คนในโลกเดียวกัน **ค่ามัธยฐานวิชาต่างวิถี = 0** (สูงสุดรองลงมาคือ 1) คัมภีร์ปราณ `MANTRA_V200_CHRONO_EPOCH_02` ก็ชื่อบ่งว่ามาจากวิถี CHRONO_EPOCH (ส่วนนี้ผมยังไม่ได้ยืนยันว่า mantra ผูกวิถีใด) สายย่อยที่เป็น `NONE` ถูกเติมเป็น `PURE_SWORD_SAINT` ภายหลังโดยกลไกคริสตัลสายย่อย (`sect.js:2460`) จึงไม่ใช่ปัญหาถาวร
- **แก้:** แทนที่จะแก้ `path` ทีหลัง ให้สร้าง NPC ด้วยวิถีที่ต้องการตั้งแต่ต้น (ส่ง `path`/`sub` เข้า `addNpc` หากรองรับ) หรือเรียกชุดเดียวกับที่ `expedition.js:5821–5850` ใช้ตอนแปรพักตร์ (เลือก `sub` จาก `CULT.PATHS[path].subPaths`, `CULT.bestMantra`, `CULT.threshold`, `CULT.initTrack`, `CULT.ensurePathGauge`, ล้าง `techs` แล้วเติมวิชาที่ตรงวิถี/ติดตัวมากับเชลย)
- **เกณฑ์ตรวจรับ:** หลังรับเชลยทุกคนเป็นศิษย์ ต้องผ่าน `PATHS[cult.path].subPaths.some(s => s.id === cult.sub)` (หรือ `sub === 'NONE'` เฉพาะกรณีที่ออกแบบว่ารอคริสตัลสายย่อย — ดูหมายเหตุ), วิชาที่ NPC ถือ ต้อง `CULT.tech(t).path ∈ {cult.path,'ANY'}` เป็นส่วนใหญ่ (ยกเว้นวิชาที่เรียนข้ามวิถีจริงตามกฎเดิม) และ mantra ต้องเป็นของวิถีเดียวกัน
- **หมายเหตุ:** `sub: 'NONE'` ถูกใช้ตั้งใจใน `sect.js:2460, 2612` (NPC ที่รอคริสตัลสายย่อย) ถ้า NONE เป็นสถานะถูกกฎของ NPC ขั้นสูง ให้ตัวตรวจ invariant ยอมรับ NONE แต่ต้องไม่มี mantra/techs ปนวิถีอื่น

## 5. ภาคผนวก: สคริปต์ตรวจที่ใช้ซ้ำได้

**N-02 — หาวิชาที่อ้างสายย่อยไม่มีจริง** (รันใน `GAME_SOURCE`)
```js
const G = require('./test/load.js'); const { CULT, JD } = G;
const al = JD.MARTIAL.SUBPATH_ALIASES || {};
const seen = new Set(), bad = [];
for (const t of JD.TECH.techniques.concat(JD.MARTIAL.techniques || [])) {
  if (seen.has(t.id)) continue; seen.add(t.id);
  if (!t.sub || t.sub === 'ANY') continue;
  const P = CULT.PATHS[t.path]; if (!P) continue;
  if (P.subPaths.some(s => s.id === t.sub)) continue;
  const a = al[t.sub];
  if (a && P.subPaths.some(s => s.id === a)) continue;
  bad.push(t.id + ':' + t.path + '/' + t.sub);
}
console.log(bad.length, bad.join('\n'));
```

**N-03 — ฟังก์ชันที่ไม่มีใครเรียกในเกม:** นับการอ้างถึงชื่อฟังก์ชันของโมดูลใหม่ทุกไฟล์ใน `js/` (ไม่รวม `test/`) ลบจำนวนการนิยาม — เหลือ 0 = ไม่มีทางเรียก

**N-01 — จับต้นกำเนิดของ NPC ที่ข้อมูลวิถีผิด:** ครอบ `W.npcs.push` เพื่อเก็บสแต็กตอนสร้าง แล้วตรวจ invariant `cult.sub ∈ PATHS[path].subPaths ∪ {'NONE'}` และ mantra/techs ตรงวิถีทุกวัน
