## 2. เป้าหมายและลำดับความสำคัญ

### P0 — ออร่าขั้นสูงสุดเฉพาะ 43 วิถี

1. สร้างหรือปรับข้อมูลลายเซ็นวิชวลให้ครอบคลุมรหัสวิถีหลักจริงครบทั้ง 43 รหัส โดยตรวจเทียบกับ Object.keys(CULT.PATHS) ไม่ใช้เพียงรายชื่อในเอกสาร
2. เมื่อ NPC อยู่ถึงขั้นสูงสุดของวิถี ให้แสดงออร่าที่สื่อวิถีนั้นได้ทันทีในฉากที่ renderer รองรับ ใช้ขั้นสูงสุดของวิถีจริง ไม่ใช้เงื่อนไขว่า stage === 9 กับทุกวิถี
3. แต่ละวิถีต้องจำแนกได้ด้วยรูปทรง/เงาร่างการเคลื่อนไหว/รูปแบบการโคจรหรือพื้นผิวประกอบกับสี ห้ามทำเพียงวงแหวนแบบเดียวแล้วสลับสี ห้ามปล่อยให้รหัสวิถีที่ถูกต้องตกไปใช้ลายกระบี่หรือเอฟเฟกต์กลาง
4. ให้แรงบันดาลใจจากธีมและกลไกที่มีจริงในวิถี เช่น กระบี่, กายา, เทวะ, มาร, จิต, กลจักร, กรรมวัฏ, ราชันย์อสูร, ปราชญ์หนุนนำ, รังสรรค์, ค่ายกลยันต์, พิชัยอภิบาล, โหราดวงดาว, พุทธธรรม, สุญญตามิติ, คีตายุทธ, พิษกู่, แปลงกาย, เทวอากาศ, จาริก, พาณิชย์, มังกรธรณี, แรงโน้มถ่วง, กาลเวลา, อักษรปราชญ์, เชิดเงาวิญญาณ, โกลาหล และวิถีอื่นที่ระบุในข้อมูลจริง ตรวจเนื้อหาของแต่ละวิถีก่อนตัดสินรูปแบบ อย่าคิดระบบเกมใหม่จากชื่อเพียงอย่างเดียว
5. ใช้ชุดข้อมูลลายเซ็นร่วมสำหรับออร่าและเอฟเฟกต์ท่าเท่าที่ทำให้ทั้งสองเข้ากันทางภาพ โดยยังให้ท่าต่อสู้มีจังหวะและองค์ประกอบเหมาะกับการโจมตี/ป้องกัน/สนับสนุนของวิชานั้น

### P1 — เอฟเฟกต์วิชาระดับสูงตามข้อมูลจริง

1. ตรวจวิชาระดับสูง/ตำนาน/วิชาต้องห้ามที่มีอยู่จริงในแต่ละวิถี และระบุท่าที่เหมาะเป็นตัวแทนจากชื่อ, ธาตุ, ประเภทอาวุธ, effect และบทบาทจริง
2. เพิ่มหรือแก้การจับคู่ signatureVfx ให้เอฟเฟกต์เกิดจากการใช้วิชาจริงผ่านเส้นทาง COMBAT → castFx → renderer ไม่สร้างเอฟเฟกต์ที่เล่นแต่ในหน้าแสดงตัวอย่าง
3. เป้าหมายคือให้แต่ละวิถีมีวิชาระดับสูงที่มองเห็นเอกลักษณ์ได้อย่างน้อยหนึ่งท่าเมื่อวิถีนั้นมีวิชาที่เหมาะอยู่ในข้อมูล ใช้รหัสวิชาจริง ตรวจว่าการจับคู่ไม่ชี้ ID ที่ไม่มีหรือชี้ผิดวิชา หากวิถีใดไม่มีวิชาที่เหมาะ ให้รายงานข้อจำกัดโดยไม่สร้างวิชาหรือกลไกปลอมเพื่อให้ครบตัวเลข
4. หลีกเลี่ยงการให้หลายวิชาที่มีธรรมชาติต่างกันใช้ภาพเดียวกันเพียงเพราะอยู่ระดับสูงหรือมีชื่อคล้ายกัน ตรวจการทำงานของ fallback ใน SK.resolveSignatureVfx และปรับให้การจับคู่สำคัญมีความชัดเจนและตรวจสอบได้

### P2 — ขยายลงสู่ระดับอื่นเมื่อเหมาะสม

- หลัง P0 ครบและ P1 มีคุณภาพแล้ว ให้พิจารณาเพิ่มออร่าหรือเอฟเฟกต์สำหรับหลายช่วงขั้น เช่น ขั้นสูง, ก่อนสูงสุด และระดับกลาง ตามความต่างของแต่ละวิถี
- ทำได้เมื่อใช้ primitives/โครงสร้างร่วมกันอย่างมีคุณภาพ ไม่ลดความแตกต่างของ 43 วิถี ไม่ทำให้ฉากรก และผ่านการตรวจประสิทธิภาพ หากทำไม่ครบภายในแพตช์ ให้ส่งมอบ P0 ที่สมบูรณ์และระบุขอบเขต P1/P2 ที่เหลือตามจริง

## 3. ทิศทางศิลป์และประสบการณ์ผู้เล่น

- ภาพต้องสื่อว่าใครฝึกวิถีใดและมีตบะถึงระดับสูงสุด โดยอ่านออกจากองค์ประกอบมากกว่าสีอย่างเดียว แต่ไม่กลบตัวละครหรือภูมิประเทศ
- เลือกกลุ่มรูปร่าง/จังหวะภาพที่สื่อวิถีจริง เช่น เส้นพลังพุ่งตรงหรือวงกระบี่, วงชีพจรและกล้ามเนื้อปราณ, เฟืองกับเส้นด้าย, วงกงกรรม, เงารอยแยกมิติ, วงแหวนกาลเวลา, อักษรที่เรียงเป็นพู่กัน, ค่ายกลภูมิประเทศ, คลื่นเสียง, เมล็ดพิษ หรือภาพสนับสนุน/รักษา ห้ามยัดสัญลักษณ์ที่ไม่เข้ากับเนื้อหาเพียงเพื่อเติมให้ครบ
- ให้สังเกตภาพจริงในฉากโลกและฉากต่อสู้ที่ขนาดตัวละครปกติ/ซูมออก รวมถึงจอมือถือ ออร่าที่มีรายละเอียดมากแต่หดจนแยกไม่ออกยังไม่ผ่าน
- ยึดระบบภาพและวิธีวาด Canvas 2D ที่โปรเจกต์มีอยู่ ไม่เพิ่มไลบรารีหรือทรัพยากรออนไลน์ อาจใช้ primitives ที่มีใน Canvas และ assets ภายในเกมตามความเหมาะสม
- เคารพตัวเลือกคุณภาพกราฟิก, การลดการเคลื่อนไหว, การลดรายละเอียดตามซูม/คุณภาพ และงบวาดฉากที่มี NPC จำนวนมาก หลีกเลี่ยงเงาเบลอ/การคำนวณหนัก/การสร้างออบเจ็กต์ซ้ำใน hot render loop หากไม่จำเป็น
- เอฟเฟกต์เป็นการแสดงผลเท่านั้น: ห้ามเปลี่ยนดาเมจ, คูลดาวน์, ผลลัพธ์การต่อสู้, RNG, AI, ความคืบหน้าการฝึก หรือข้อมูลเซฟเพียงเพื่อรองรับภาพ ใช้สถานะวิถี/ขั้น/วิชาและ event จริงที่มีอยู่
- ใช้เวลา renderer ที่มีอยู่และ phase ที่คำนวณจากข้อมูลตัวละครอย่างคงที่ ห้ามใช้ Math.random() หรือ W.rng ในการวาด และห้ามให้การวาดเปลี่ยนสถานะเกม/ผล serialize
- รักษา GAME_SOURCE/js/human_core.js ให้ byte-identical และรักษาจำนวน/ลำดับแท็กสคริปต์ใน GAME_SOURCE/index.html และ GAME_SOURCE/test/load.js ตามกฎใน AGENTS.md

## 5. เกณฑ์รับงาน

### ความครอบคลุมและความถูกต้อง

- ชุดทดสอบยืนยันว่าลายเซ็นวิชวลมี key ตรงกับวิถีจริงครบ 43/43 ไม่มี path ID จริงที่ใช้ fallback เป็นลายกระบี่
- ทุกวิถีวาดออร่าที่ CULT.PATHS[pathId].maxStage ได้โดยไม่โยนข้อผิดพลาด และข้อมูลสอดคล้องกับชื่อ/ธีม/เนื้อหาในเกม
- ภาพอย่างน้อยสามวิถีที่ต่างกันมากต้องมีรูปทรงและการเคลื่อนไหวต่างกันชัด ไม่ใช่เพียงสีคนละชุด และภาพของขั้นสูงสุดต้องมีน้ำหนักพอแยกจากขั้นทั่วไป
- วิชาระดับสูงที่จับคู่แล้วต้องมีอยู่จริงและเล่นผ่านการใช้วิชาใน combat จริง ตรวจว่าทั้งโจมตี, สนับสนุน/รักษา, ป้องกัน หรือเรียกอสูรได้รับภาพที่เหมาะสมตามชนิดท่าที่มีอยู่
- ขั้นสูงสุดของวิถีที่มี maxStage 4, 5, 8 และ 9 ต้องได้รับการทดสอบตามเพดานจริงของแต่ละวิถี

### ความปลอดภัยของระบบและประสิทธิภาพ

- การวาดไม่เปลี่ยน SIM.serialize(W), สถานะตัวละคร, combat state, หรือ RNG ก่อน/หลังการวาด
- Canvas context คืนสถานะได้ครบ ไม่มี save/restore รั่วหรือข้อผิดพลาดเมื่อข้อมูลวิถี/วิชาหายหรือไม่รู้จัก
- โหมดลดการเคลื่อนไหว/คุณภาพกราฟิกต่ำ/ซูมออกยังคงเล่นได้และไม่ทำให้ภาพซ้อนรก วัดหรือทดสอบผลต่อการวาด NPC จำนวนมากตามเครื่องมือที่มี
- ไม่มีการเปลี่ยนสมดุลหรือ save schema สำหรับเอฟเฟกต์ที่คำนวณจากข้อมูลเดิม หากจำเป็นต้องเพิ่มข้อมูลถาวร ให้พิสูจน์เหตุผลและตรวจเซฟ/โหลดตามระบบของโปรเจกต์
- human_core.js ไม่เปลี่ยน และ build เกมไฟล์เดี่ยวตรงกับโมดูลต้นฉบับ
