# พรอมต์สำหรับ Gemini — แพตช์ถัดไปจากรายงานใหม่ 13 ฉบับ

ใช้ ZIP โปรเจกต์ฉบับเต็มจากสาขา `main-debug` ที่แนบเป็นฐานพัฒนา อ่าน `AGENTS.md` ก่อนเริ่มทุกครั้ง เอกสารนี้คือรัฐธรรมนูญของเกม ห้ามแก้เนื้อหา ย้าย ลบ หรือเปลี่ยนกฎใน `AGENTS.md` เว้นแต่เจ้าของเกมสั่งหรืออนุญาตอย่างชัดเจน

## เป้าหมายรอบนี้

ผู้ใช้กำหนดให้เอกสารใหม่ 13 ฉบับใน `bug reports/` เป็นงานแพตช์ถัดไป อ่านครบทั้ง 13 ฉบับ ตรวจซ้ำกับซอร์สและการทดสอบใน ZIP แล้วตัดสินใจและลงมือแก้ข้อที่ยังมีอยู่จริง โดยเชื่อมผลให้ครบทั้งเกม อัปเดตเอกสาร/สกิลที่ได้รับผล และส่ง ZIP โปรเจกต์ฉบับเต็มที่ตรวจแล้วกลับให้ผู้ใช้ เมื่อจบขอบเขตนี้ให้หยุดรอคำสั่งถัดไป

**คำสั่งใหม่นี้มีลำดับเหนือพรอมต์เก่าที่ฝังใน `bug reports/`** เช่นคำสั่งจาก `00_READ_ME_FIRST.txt` ที่ให้ทำหมวด 07–08 โดยใช้เกมจากแชท Gemini เก่า ให้ใช้ซอร์สล่าสุดใน ZIP นี้เป็นฐานและทำชุดเอกสารใหม่ 13 ฉบับตามคำสั่งผู้ใช้ปัจจุบัน ห้ามย้อนเอาโค้ดหรือเอกสารเก่ามาทับงานที่มีใน ZIP หากพบความขัดแย้งให้บันทึกและยึดคำสั่งผู้ใช้ล่าสุดกับ `AGENTS.md`

## เอกสารที่ต้องอ่าน

ตรวจว่ามีรายงานใหม่ครบ 13 ฉบับตาม `git` snapshot และ `bug reports/MANIFEST.json` จากนั้นอ่าน PDF ทุกหน้าและเอกสารประกอบที่เกี่ยวข้อง:

1. `14A`, `14B`, `14C` — พงศาวดาร รายงาน ตัวชี้วัดที่มีอยู่ สำนวนตามเหตุการณ์/วิถี เสียงผู้รายงาน ความคิด NPC คำบรรยายสถานที่ และลำนำข่าว
2. `15` — ตรวจชื่อไทยของ 43 มหาวิถีและ 286 สายย่อย ให้เหมาะกับ UI
3. `16A`, `16B` — เกลาชื่อไทยที่ผู้เล่นเห็นในระบบต่าง ๆ เช่น นิสัย สถานะ VFX การปกครอง ไอเทม วิชา โลก และแดนเทพ
4. `LORE_01A`, `LORE_01B` — กฎจักรวาล ม่านกั้นภพ ลำดับผู้อาศัยโลกเบื้องบน ห้ามหาพิภพ อเวจี และสุญญากาศนอกเอกภพ
5. `LORE_02A` ทั้งสองฉบับ, `LORE_02B`, `LORE_02C`, `LORE_02D` — ที่มาและระดับของศาสตรา/วิชาในตำนาน กฎเปรียบเทียบโลก การตรวจข้อขัดแย้ง และผลสะเทือนต่อประวัติตัวละคร/เหตุการณ์

อ่าน `bug reports/00_READ_ME_FIRST.txt`, `00_JS2_MASTER_INDEX...`, `MANIFEST.json`, สถานะเกม และสกิล/ทะเบียนที่เกี่ยวข้องเพื่อทำความเข้าใจที่มา แต่ถือรายงานเป็นข้อค้นพบหรือข้อเสนอที่ต้องพิสูจน์ ไม่ใช่ข้อเท็จจริงของซอร์สล่าสุดโดยอัตโนมัติ รายงานสองฉบับชื่อ `LORE_02A` มีกรอบเล่าต่างกัน ให้เปรียบเทียบกับ `LORE_02C` และ `LORE_02D` แล้วหาข้อสรุปที่สอดคล้องกันก่อนแก้

## หลักการตัดสินใจและขอบเขต

- ยึดเกมจำลองโลกยุทธภพที่ NPC ตัดสินใจเอง โลกดำเนินตามการกระทำและเหตุ–ผลของ NPC ผู้เล่นสังเกต แก้สถานะ และเสกของได้ แต่ห้ามเพิ่มการบังคับตัวละคร/สำนักหรือการตัดสินใจแทน NPC
- ตรวจสถานะในซอร์สและทดสอบทีละข้อ จัดหมวดเป็น: ยังเป็นบัค, แก้แล้วในฐานปัจจุบัน, ข้อเสนอด้านเนื้อหา, ขัดกับ canon/ข้อมูลจริง หรือยังพิสูจน์ไม่ได้ ระบุไฟล์/ฟังก์ชัน/หลักฐาน อย่าทำบัคซ้ำและอย่าเชื่อป้าย “verified” โดยไม่ตรวจ
- แยกข้อเท็จจริงที่บันทึกไว้ ข้อมูลที่ NPC รู้ ข่าวลือ ความเชื่อ และถ้อยคำเชิงวรรณศิลป์ออกจากกัน ห้ามรายงานสร้างตัวเลข เหตุการณ์ สาเหตุ เจตนา ความคิด ความสัมพันธ์ หรือความรู้ที่ไม่มีในสถานะจริง/หลักฐานของเกม
- ระบบรายงานต้องเล่าเหตุที่เกิดขึ้นจริง ใช้ตัวเลขจากระบบเดียวกับที่บันทึก/คำนวณอยู่ ไม่อ่านความลับหรืออนาคตที่ตัวละครไม่รู้ UI/Canvas อ่านสถานะอย่างเดียว ไม่สุ่มและไม่เปลี่ยนโลก
- การปรับชื่อให้แก้เฉพาะข้อความแสดงผล เช่น `nameTh`/dictionary ตามสถาปัตยกรรมจริง ห้ามเปลี่ยน ID, key, alias, save field, สูตร, การอ้างอิง หรือพฤติกรรมเพื่อให้ชื่อดูสวย ตรวจว่าความหมายไทยตรงระบบ ไม่ยาว/ล้นบนมือถือ และไม่ใช้ชื่อเดียวจนผู้เล่นแยกสิ่งต่างชนิดกันไม่ได้
- Lore ใหม่ต้องไม่ทำให้ข้อมูลตัวละคร เหตุการณ์ เบาะแส ไอเทม วิชา หรือรายงานขัดกัน ให้ติดตามผลกระทบไปถึงไฟล์ canon ทุกแหล่งที่เกี่ยวข้อง รวมประวัติตัวละคร/เหตุการณ์ที่ `LORE_02D` ระบุ
- ใช้กฎจักรวาลที่พิสูจน์จากเอกสารต้นทางและซอร์ส สังเกตความต่างระหว่าง “คนโลกเบื้องล่างโอ้อวด/เข้าใจผิด” กับความจริงเชิงจักรวาล ห้ามลดทอนความสำเร็จและความยิ่งใหญ่ของโลกมนุษย์อย่างเหมารวม หรือยกระดับอุปกรณ์จนขัดกฎม่านกั้นภพโดยไม่ตั้งใจ
- **คุณมีอิสระคิด วิเคราะห์ สร้างทางเลือก และตัดสินใจวิธีทำงานเองได้เต็มที่** ไม่จำเป็นต้องทำตามข้อเสนอใน PDF ทุกข้อ และเสนอแนวทางที่ดีกว่าได้ หากมีเหตุผลจากซอร์สและเป้าหมายเกม รองรับให้เลือก รับ ปรับ รวม หรือปฏิเสธข้อเสนอ พร้อมบันทึกเหตุผลและหลักฐาน
- อิสระดังกล่าวอยู่ภายในขอบเขตแพตช์และต้องไม่ขัด `AGENTS.md` ซึ่งเป็นรัฐธรรมนูญของเกม หากข้อเสนอหรือวิธีแก้ใดขัดกับ `AGENTS.md` ให้ยึด `AGENTS.md` และหาทางเลือกที่สอดคล้อง ห้ามแก้รัฐธรรมนูญหรือทำให้อ่อนลงเพื่อให้ข้อเสนอนั้นใช้ได้

## วิธีทำงานและการตรวจ

1. ตรวจ branch/snapshot ของ ZIP, สถานะเกมล่าสุด, ไฟล์ทดสอบ, สกิล และ manifest ก่อนเริ่ม อย่าใช้ไฟล์จากประวัติหรือ ZIP ซ้อนมาทับซอร์สปัจจุบัน
2. ทำตารางข้อค้นพบทั้ง 13 ฉบับ: เอกสาร/หัวข้อ, ID หรือ API, สถานะที่พบจริง, แหล่งสร้างและผู้ใช้ข้อมูล, ผลกระทบข้ามระบบ, การตัดสินใจ, วิธีทดสอบ
3. แบ่งลงมือเป็นสามสายที่เชื่อมกัน: (ก) พงศาวดาร/รายงาน/สำนวนและคำบรรยาย (14A–14C), (ข) ชื่อไทยและ UI (15–16B), (ค) lore/ระดับจักรวาล/ความต่อเนื่องของตำนาน (LORE 01A–02D) ปรับลำดับหรือแบ่งงานย่อยได้เมื่อมีเหตุผล แต่ตรวจความเชื่อมโยงร่วมก่อนส่ง
4. ไล่ผลกระทบจากแหล่งข้อมูล → AI/ผู้บันทึก → สถานะโลก → รายงาน/ข้อความ UI → เซฟ/โหลดและผลระยะยาว แก้ทุกผลต่อเนื่องที่จำเป็นต่อข้อค้นพบในขอบเขตนี้ เก็บงานนอกขอบเขตเป็นรายการค้าง ไม่ขยายไปทำหมวดเก่าหรือ roadmap ทั้งหมดเอง
5. ใช้ tests ที่มีอยู่และเพิ่ม/แก้เฉพาะ regression ที่จำเป็น รันชุดทดสอบที่เกี่ยวข้อง, schema/syntax checks, standalone build และชุดทดสอบหลักตามที่สภาพแวดล้อมรองรับ ตรวจลายนิ้วมือ/ไฟล์ล็อกของ `human_core.js`, จำนวนและลำดับ script tags, ความบริสุทธิ์ของ renderer/RNG และงบประสิทธิภาพตาม `AGENTS.md` รายงานตามผลจริง รวมความล้มเหลว/timeout ที่มีอยู่ ห้ามปิดหรือผ่อนการทดสอบเพื่อให้ผ่าน
6. อัปเดต `project_status_and_ai_onboarding.md`, สกิลที่กระทบ, สารบัญและรายงานแพตช์ให้ตรงซอร์สจริง แยกของที่ทำแล้ว ข้อจำกัด และงานค้าง ห้ามแก้ `AGENTS.md`
7. สร้าง ZIP ฉบับเต็มของโปรเจกต์ล่าสุดที่คงทุกงานใน ZIP ตั้งต้นไว้ รวมซอร์ส, assets ที่เกมใช้, bug reports, skills, tools/tests/dependencies, standalone ที่ build จากซอร์ส, และเอกสารที่อัปเดต ไม่ใส่ `.git`, cache หรือ ZIP ซ้อน ตรวจ `testzip`/CRC, directory entries, รายการไฟล์และไฟล์สำคัญ และทดลองแตกไฟล์ก่อนส่ง
8. ส่งลิงก์ ZIP พร้อมสรุปสิ่งที่แก้ สิ่งที่ไม่รับ/ค้าง และผลทดสอบ ถ้าไม่มีสิทธิ์ push GitHub ให้พูดตรง ๆ ว่าเป็น ZIP สำหรับผู้ใช้อัปโหลด อย่าอ้างว่า push แล้ว หลังส่งให้หยุดรอผู้ใช้
