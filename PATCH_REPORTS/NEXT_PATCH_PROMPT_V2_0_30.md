## 🧭 1. กฎเหล็กและข้อกำหนดสถาปัตยกรรม (Architectural Invariants & Core Rules)

ก่อนเริ่มเขียนโค้ด ให้ปฏิบัติตามกฎเหล็กของโครงการ JianghuSect Evolution อย่างเคร่งครัด:

1. **ห้ามแตะต้องไฟล์ `GAME_SOURCE/js/human_core.js` เด็ดขาด (Core Lock Invariant):**
   - ไฟล์นี้ถูกล็อกลายนิ้วมือ `HC.FINGERPRINT === '155:2f9c9dd7'` ห้ามแก้ไขแม้แต่อักขระเดียวหรือเคาะเว้นวรรค
   - ตรวจสอบความถูกต้องด้วย: `node test/core_lock.js`
   - หากต้องการเพิ่มคุณสมบัติ พฤติกรรม หรือตรรกะตัวละคร ให้ต่อยอดที่ `js/expedition.js`, `js/sect.js`, `js/cognition.js`, `js/ai.js` หรือ `js/cultivation.js`
2. **รักษาจำนวนและลำดับ `<script>` ให้ตรงกัน 100%:**
   - มี `<script>` ทั้งหมด **40 แท็ก** ใน `GAME_SOURCE/index.html` และต้องมีลำดับโหลดตรงกันกับ `GAME_SOURCE/test/load.js` เว้นแต่ผู้ใช้จะสั่งปรับเปลี่ยนโดยตรง
3. **รวมไฟล์เกมออฟไลน์เดี่ยวเสมอ (Single-File Offline Bundle):**
   - ทุกครั้งที่แก้ไขโค้ดใน `GAME_SOURCE/js/`, `GAME_SOURCE/data/` หรือ `GAME_SOURCE/css/` จะต้องรัน:
     ```bash
     cd GAME_SOURCE && node tools/build_single.js
     ```
     เพื่อสร้างและอัปเดต `GAME_SOURCE/JianghuSect_single.html` ให้ตรงกับซอร์สโค้ดล่าสุดเสมอ
4. **ความถูกต้องของ Schema ข้อมูล (Data Integrity):**
   - เมื่อเพิ่มไอเทม ตำรับ หรือข้อมูลใดๆ ต้องรันตรวจสอบ schema:
     ```bash
     cd GAME_SOURCE && node tools/validate_data_schema.js
     ```
     ต้องผ่านโดยมี **0 errors / 0 warnings**
5. **ภาษาและข้อความในเกม (Thai Localization):**
   - ข้อความทั้งหมดที่ผู้เล่นมองเห็น (ชื่อ, คำอธิบาย, บันทึกพงศาวดาร, เมนู UI, บทสนทนา) ต้องเป็น **ภาษาไทย** ที่สละสลวย เข้ากับสำนวนกำลังภายในและนิยายเทพเซียน
6. **ไม่จำเป็นต้องรักษาความเข้ากันได้กับเซฟเก่า (No Backward Save Compatibility):**
   - ผู้ใช้อนุญาตให้ปรับปรุง พัฒนา หรือต่อยอด Save Schema / โครงสร้างข้อมูลได้อย่างเต็มที่เพื่อความก้าวหน้าของระบบ ไม่ต้องกังวลว่าเซฟเก่าจะเปิดได้หรือไม่
   - แต่ระบบบันทึกและโหลดเกมที่สร้างบนเวอร์ชันปัจจุบัน (v2.0.30) ต้องสามารถ Save/Load ได้อย่างสมบูรณ์แบบโดยข้อมูลไม่สูญหาย (Round-Trip Serialization Integrity)
7. **งบประมาณเวลาประมวลผล (Performance Budget):**
   - รักษางบเวลาการประมวลผลของ `SIM.tick` ให้น้อยกว่า 3.0 ms ต่อ tick เพื่อความลื่นไหลบนเบราว์เซอร์
   - NPC ภายนอกสำนักไม่ต้องรัน Loop เดินทางรายนาทีแบบละเอียด ให้ใช้ระบบจำลองเชิงสถิติ/รายเดือน (Statistical/Monthly Simulation) เว้นแต่จะถูกรับเข้าสำนักด้วยระบบ Hydration

## 🏛️ 2. บริบทและรากฐานปัจจุบัน (Baseline Context v2.0.29)

ในเวอร์ชัน v2.0.29 ระบบได้สร้างรากฐานสำคัญไว้แล้ว ได้แก่:
1. **ระบบแปลงสภาพยอดคนภายนอกเข้าสำนักสมบูรณ์ (`X.hydrateFigureToNpc` ใน `js/expedition.js`):**
   - แปลงบุคคลจากโครงสร้างภายนอกสำนัก (`figures`) เข้าสู่ `W.npcs` และ `W.byId` ของสำนักผู้เล่น โดยรักษานิสัยเดิม (`h.personality`: ambition, integrity, aggression ฯลฯ), คุณค่า (`h.values`), ทักษะสังคม, สติปัญญา, วิถีการบ่มเพาะ (`path`, `stage`, `sub`, `techs`) และอาวุธสวมใส่เดิมไว้ 100% โดยไม่สุ่มใหม่
2. **การแปรพักตร์จากศึกชิงบัลลังก์สำนัก (`X.resolveSectSuccession`):**
   - ทายาทหรือผู้สืบทอดที่พ่ายแพ้ในศึกชิงตำแหน่งเจ้าสำนัก หากมีความระมัดระวังตัว (`succCaut >= 40`) จะหนีตายหรือแปรพักตร์มาขอพึ่งพิงสำนักผู้เล่น
3. **ระบบพงศาวดารพิราบสื่อสารฉบับอรรถรส (`UI.rLog` ใน `js/ui.js`):**
   - แยกหมวดหมู่เหตุการณ์ยุทธภพ (`all`, `BATTLE`, `SUCCESSION`, `FACTION`, `SECRET_REALM`, `LEGEND`, `VISITOR`) พร้อมช่องค้นหาข้อความแบบเรียลไทม์ (`#worldChronicleSearch`)

### เสาหลักที่ 1: ขยายโครงสร้างตำแหน่งสำนักภายนอกและระบบคิดหลายระดับ (Expanded Foreign Sect Offices & Multi-Tier Cognition)

#### รายละเอียดเชิงเทคนิค:
- ใน `W.world.sects[sId]` (ซึ่งเดิมมี `figures.master`, `figures.deputy`, `figures.successor`):
- ให้ขยายโครงสร้าง `figures` ให้รองรับตำแหน่งผู้อาวุโสเฉพาะทาง (Specialized Domain Elders) และศิษย์เอก:
  1. `figures.disciplineElder` (ผู้อาวุโสหอวินัย - 戒律长老): มีค่า `integrity` และ `aggression` สูง คอยดูแลกฎสำนักและการตามล่าผู้แปรพักตร์
  2. `figures.craftElder` (ผู้อาวุโสหอโอสถ/หลอมสร้าง - 炼丹长老): มีทักษะปรุงยาหรือตีเหล็กสูง ดูแลการแลกเปลี่ยนทรัพยากร
  3. `figures.warMarshal` (ผู้อาวุโสการทูต/แม่ทัพศึก - 征伐长老): มีพลังรบสูง รับผิดชอบการยกทัพตรวจการณ์และป้องกันค่าย
  4. `figures.coreDisciples` (ทำเนียบศิษย์เอก - 核心弟子): ลิสต์ศิษย์หัวกะทิ 2–4 คน (Tier 3)
- **การจำลองความคิดแบบแยกชั้น (Hierarchical Cognition Tiers):**
  - **Tier 1 (ผู้นำสูงสุด):** มีบทบาทในการตัดสินใจนโยบายใหญ่ของสำนัก พันธมิตร หรือสงคราม
  - **Tier 2 (ผู้อาวุโสเฉพาะทาง):** ตรวจสอบเฉพาะหน้าที่ของตน เช่น ผู้อาวุโสหอวินัยตรวจพบว่ามีศิษย์หนีไปสำนักอื่น จะเป็นผู้ยื่นคำร้องให้ออก "สารทวงตัว"
  - **Tier 3 (ศิษย์เอก):** ร่วมงานประลองยุทธภพ หรือมีโอกาสถูกชักชวนแปรพักตร์
- ตัวละครทุกตำแหน่งในโครงสร้างนี้ ต้องสามารถถูก Hydrate เข้าสำนักผู้เล่นได้ทันทีด้วย `X.hydrateFigureToNpc` เมื่อเกิดเงื่อนไขที่เหมาะสม

### เสาหลักที่ 2: ระบบยอดคนอิสระไร้สังกัดแบบสุ่มอุบัติ (Emergent Unaffiliated Figures / Wandering Solitary NPCs)

#### รายละเอียดเชิงเทคนิค:
- เพิ่มคลังข้อมูลยอดคนพเนจรในสถานะโลก: `W.world.wanderingFigures` (หรือ `W.wandering`)
- ฟังก์ชันจำลองการเกิดและการเดินทาง: `X.tickWanderingFigures(W)` รันทุกเดือน (`SIM.monthly`)
  - โอกาสเกิดตามฤดูกาลหรือตามข่าวลือฟ้าดิน (ความหนาแน่นรวมในยุทธภพประมาณ 4–8 คน ไม่ให้ล้นความจำ)
- **4 ต้นแบบยอดคนอิสระ (Unaffiliated Archetypes):**
  1. `SWORD_SEEKER` (จอมยุทธ์พเนจรแสวงหาคู่ประลอง): สุ่มเดินทางไปยังโหนดต่างๆ บนแผนที่โลก หากเดินทางมาถึงสำนักผู้เล่น จะมีเหตุการณ์ขอท้าดวลกับศิษย์เอกผู้เล่น ศิษย์ที่ชนะจะได้ค่าชื่อเสียงและตบะก้าวกระโดด
  2. `HERMIT_DOCTOR` (หมอยาเทวดาเร้นกาย): เร้นกายตามหุบเขาหรือป่าสมุนไพร หากคณะเดินทางผู้เล่นไปพบ สามารถขอซื้อโอสถหายาก หรือขอให้ช่วยรักษาอาการบาดเจ็บสาหัสของศิษย์
  3. `UNORTHODOX_BANDIT` (จอมโจรคุณธรรม / ผู้บำเพ็ญนอกรีต): ปล้นชิงคาราวานของสำนักฝ่ายอธรรม หรือช่วยเหลือผู้ลี้ภัย สามารถผูกมิตรหรือปราบปรามได้
  4. `ROGUE_ARRAYIST` (นักวางค่ายกลพเนจร): ขายแผ่นหยกค่ายกลโบราณ หรือบอกพิกัดแดนลับแห่งใหม่
- **การชักชวนเข้าสำนัก:** หากผู้เล่นสร้างสัมพันธ์ดี มีค่าชื่อเสียงสำนักสูง หรือช่วยเหลือยามคับขัน สามารถชักชวนยอดคนเหล่านี้เข้าสำนักได้ โดยใช้ `X.hydrateFigureToNpc` แปลงเข้าสู่ระบบ `W.npcs` ของสำนักผู้เล่น

### เสาหลักที่ 3: สารทวงตัวผู้ลี้ภัยและการตามล่าข้ามสำนัก & ศึกทวงคืนสำนักเดิม (Renegade Pursuit & Vendetta Reclamation)

#### รายละเอียดเชิงเทคนิค:
- เมื่อศิษย์ภายนอกแปรพักตร์หรือหนีภัยมาอยู่กับสำนักผู้เล่น (เช่น จากศึกชิงบัลลังก์):
  - ระบบจะบันทึกสถานะ `h.renegadeOrigin = { sectId, formerPost, bounty, offenseType }`
- **การส่ง "สารทวงตัวข้ามสำนัก" (Extradition Ultimatum):**
  - ในเวลา 1–3 เดือนถัดมา สำนักเดิม (ขับเคลื่อนโดยผู้อาวุโสหอวินัย `disciplineElder`) จะส่งทูตหรือพิราบสื่อสารมายังสำนักผู้เล่น
  - แสดงหน้าต่างแจ้งเตือน/ตัวเลือกการตัดสินใจ (Event Dilemma Dialog):
    1. **ปกป้องศิษย์ (Defy & Protect):**
       - ผล: ศิษย์เกิดความซาบซึ้งใจอย่างลึกซึ้ง (`gratitude +50`, ค่าความจงรักภักดีเต็มร้อย) แต่สำนักเดิมจะลดระดับความสัมพันธ์ลงอย่างมาก (-40 ถึง -60) และอาจส่งมือสังหารมาลอบโจมตี หรือตัดสัมพันธ์ทางการค้า
    2. **เจรจาประนีประนอมด้วยศิลาวิญญาณ (Indemnity Settlement):**
       - ผล: จ่ายหินวิญญาณหรือโอสถล้ำค่าเพื่อไถ่ตัวศิษย์อย่างเป็นทางการ ความสัมพันธ์ไม่ตกต่ำ และศิษย์พ้นจากข้อกล่าวหา
    3. **ส่งตัวผู้ลี้ภัยคืน (Extradite Renegade):**
       - ผล: ส่งตัวศิษย์กลับไปรับโทษ ความสัมพันธ์กับสำนักเดิมดีขึ้น แต่ชื่อเสียงคุณธรรมของสำนักผู้เล่นจะลดลง และศิษย์คนอื่นๆ ในสำนักจะสูญเสียขวัญกำลังใจ
- **ศึกทวงคืนสำนักเดิม (Vendetta Reclamation Quest):**
  - หากเลือกปกป้องศิษย์ และฝึกฝนจนศิษย์คนนั้นมีตบะถึงขั้นสูง (เช่น ขั้น 5 ขึ้นไป)
  - จะปลดล็อกคำสั่งพิเศษในหน้าสำนัก/การทูต: **"เปิดศึกทวงคืนสำนัก [ชื่อสำนักเดิม]"**
  - ผู้เล่นสามารถจัดทัพสำรวจไปช่วยศิษย์ผู้นี้ทำศึกชิงสำนักเดิมคืน หากชนะ ศิษย์ผู้นี้จะได้รับสถาปนาเป็น **เจ้าสำนักคนใหม่ของสำนักนั้น** และเปลี่ยนสำนักดังกล่าวให้เป็น **สำนักพันธมิตรเอกถาวร (Eternal Sworn Ally)** หรือส่งบรรณาการให้สำนักผู้เล่นเป็นประจำทุกปี!

### เสาหลักที่ 4: ระบบคู่บำเพ็ญ สายเลือดตระกูล และทายาทรุ่นถัดไป (Taoist Companions & Clan Bloodlines)

#### รายละเอียดเชิงเทคนิค:
- **การผูกวาสนาคู่บำเพ็ญ (Taoist Companion Rite):**
  - ศิษย์ในสำนัก 2 คนที่มีความผูกพันลึกซึ้ง (ค่าความสัมพันธ์ `affection >= 70`) สามารถทำพิธีแต่งงาน/ผูกวาสนาเป็นคู่บำเพ็ญได้
  - บันทึกสถานะคู่บำเพ็ญในตัวละคร (`h.companionId`) และในสำนัก `W.sect.companions`
- **โบนัสการฝึกปราณคู่ (Dual Cultivation Synergies):**
  - เมื่อคู่บำเพ็ญอยู่ในสำนักเดียวกัน อัตราการสะสมตบะเพิ่มขึ้น 20–30% และลดโอกาสเกิดอาการธาตุไฟเข้าแทรก (`heartDemon`) ลงอย่างมาก
- **การกำเนิดทายาทผู้ฝึกตน (Next-Generation Offspring):**
  - ในแต่ละปี มีโอกาสที่คู่บำเพ็ญจะให้กำเนิดทายาท (จำลองการตั้งครรภ์และคลอด)
  - ทายาทจะสืบทอด:
    - **รากปราณ (Elemental Roots):** หลอมรวมจากธาตุเด่นของบิดาและมารดา (มีโอกาสเกิดรากปราณกลายพันธุ์ เช่น วายุ, อัสนี, น้ำแข็ง)
    - **พรสวรรค์สายเลือด (Bloodline Traits):** โบนัสค่าสถานะหรือวิชาพิเศษประจำตระกูล
    - **นามสกุล:** ใช้แซ่/นามสกุลเดียวกันกับบิดาหรือมารดา
  - เมื่อทายาทเติบโตถึงวัย (อายุ 14–16 ปี) จะเข้าสู่ระบบสำนักในฐานะศิษย์รุ่นเยาว์ที่มีพรสวรรค์สูง เพื่อรองรับการเล่นระยะยาวหลายสิบหลายร้อยปี

### เสาหลักที่ 5: สงครามพันธมิตรร่วมและการปิดล้อมค่ายสำนักใหญ่ (Coalition Sect War & Grand Siege)

#### รายละเอียดเชิงเทคนิค:
- ต่อยอดระบบสภา 3 ขั้วยุทธภพ (`ORTHODOX`, `UNORTHODOX`, `NEUTRAL`):
- **การรวมทัพพันธมิตรบุกตีสำนักศัตรู (Joint Coalition Offensive):**
  - เมื่อผู้เล่นต้องการเปิดศึกกับสำนักคู่อริ สามารถส่งสารเทียบเชิญสำนักพันธมิตรที่มีค่าความสัมพันธ์สูง (`relation >= 60`) 1–2 สำนัก มาร่วมส่งกำลังพล
  - ผู้อาวุโสแม่ทัพศึก (`warMarshal`) ของสำนักพันธมิตรจะนำกองกำลังมาร่วมจัดทัพ ทำให้พลังรบรวมของกองทัพสูงขึ้นอย่างมีนัยสำคัญ
- **การตั้งรับการปิดล้อมสำนักและการเรียกกองหนุน (Siege Defense & Reinforcement Beacon):**
  - เมื่อสำนักผู้เล่นถูกสำนักศัตรูยกทัพใหญ่มาปิดล้อม สามารถจุดควันสัญญาณหรือส่งพิราบขอความช่วยเหลือฉุกเฉินไปยังสำนักพันธมิตร
  - มีโอกาสที่กองทัพพันธมิตรจะเดินทางมาช่วยตีขนาบหลังกองทัพศัตรู พลิกสถานการณ์สงครามได้

### เสาหลักที่ 6: สมุดบันทึกประวัติศาสตร์สำนักและเสียงประกอบเชิงบรรยากาศ (Chronicle Timeline & Atmospheric Audio)

#### รายละเอียดเชิงเทคนิค:
- **หน้าต่าง Interactive Chronicle Timeline (ทำเนียบประวัติศาสตร์):**
  - เพิ่มหน้าต่างหรือแท็บย่อยใน `UI.rLog` แสดงไทม์ไลน์ประวัติศาสตร์สำนักตั้งแต่เริ่มก่อตั้ง
  - แสดงหมุดเหตุการณ์สำคัญตามปีและเดือน:
    - การก่อตั้งสำนัก / การสถาปนาเจ้าสำนักแต่ละรุ่น
    - เหตุการณ์ศิษย์บรรลุขั้นเซียนและเหินเวหาขึ้นสู่เบื้องบน
    - ชัยชนะในสงครามใหญ่และการยึดครองจุดยุทธศาสตร์
    - การสร้างศาสตราวุธระดับตำนานสำเร็จ
    - การผูกวาสนาคู่บำเพ็ญและการกำเนิดทายาทสายเลือดสำคัญ
- **ระบบเสียงบรรยากาศด้วย Web Audio API (Atmospheric Audio Engine):**
  - **ห้ามใช้ไฟล์ MP3 หรือ WAV ภายนอก** เพื่อรักษาความเป็น 100% Offline-First Self-Contained
  - ใช้ `AudioContext` ของ HTML5 สังเคราะห์เสียงด้วย Oscillators:
    - เสียงเคาะระฆังทองสำนัก (Resonant Zen Bell) เมื่อมีการบันทึกเหตุการณ์ประวัติศาสตร์หรือทะลวงด่านสำเร็จ
    - เสียงปะทะของศาสตรา (Crisp Blade Clash) เมื่อเริ่มการต่อสู้
    - เสียงพิณโบราณสั้นๆ (Pentatonic Guqin Chime) เมื่อเปิดหน้าพงศาวดาร
  - มีปุ่มเปิด/ปิดเสียงในหน้า UI สำหรับผู้เล่นที่ไม่ต้องการเสียง
