1. ฐานงานและเป้าหมาย
ใช้โปรเจกต์ล่าสุดที่คุณแก้จนถึงหมวด 06 ในแชทนี้เป็นฐานงานต่อ รักษาการแก้ไขหมวด 01–06 และงานอื่นที่ทำไปแล้ว ZIP ที่แนบนี้เป็นชุดเอกสารประกอบจาก main-debug ซึ่งซอร์สเกมในสาขานั้นยังพัฒนาเพียงหมวด 01 จึงต้องนำมาใช้เป็นข้อมูลอ้างอิงและคำแนะนำ ห้ามนำฐานเกมเก่ามาทับโปรเจกต์ที่คุณแก้ไปแล้ว เอกสารสถานะ สกิล รายงาน และพรอมต์เก่าอาจอธิบายฐานก่อนงานล่าสุดของคุณ ให้เทียบความต่างและรวมข้อมูลอย่างระมัดระวัง

เป้าหมายรอบนี้คือทำหมวด 07 และ 08 ให้ครบตามข้อค้นพบที่ตรวจแล้วว่ามีจริง พร้อมตรวจผลกระทบลูกโซ่และส่ง ZIP โปรเจกต์ฉบับเต็มหลังจบทั้งสองหมวด ผู้ใช้ต้องการรับ ZIP มาตรวจเมื่อจบสองหมวดนี้ก่อน แล้วจึงกำหนดรอบถัดไป ไม่เริ่มทำหมวด 09–12 ทั้งหมวดต่อเอง

อ่าน PROMPT_GEMINI_07_08_TH.txt ฉบับนี้, AGENTS.md ของโปรเจกต์และสำเนาที่แนบ, START_HERE_FOR_AI.md, project_status_and_ai_onboarding.md และสกิลที่เกี่ยวข้องใน .agents/skills/ ตรวจคำสั่งย่อยในโฟลเดอร์ที่จะทำงานด้วย คำสั่งปัจจุบันของผู้ใช้มีลำดับเหนือใบสั่งงานเก่า พรอมต์และแผนระยะก่อนที่ทำเสร็จแล้วเป็นประวัติ ไม่ใช่คำสั่งให้ย้อนกลับไปเริ่มแพตช์นั้นใหม่

อ่านเนื้อหาทุกไฟล์ใน bug reports/ ให้ครบก่อนแก้ รวม 00 สารบัญ/แผนงาน, หมวด 01–12 ทั้งชุด, PDF ภาพรวม, DOCX ตรวจสอบหมวด 04–05 และ 05H ของ Codex ห้ามอ่านเฉพาะชื่อไฟล์ บทสรุป หรือหมวด 07–08 แล้วอ้างว่าอ่านครบ หากไฟล์ใดอ่านไม่ได้ มีหน้าขาดหรือข้อความตัด ให้บันทึกชื่อและขอบเขตที่อ่านได้ตามจริง ใช้ manifest ตรวจความครบของรายการ หากปัญหานั้นขัดขวางการตัดสินใจ ให้รายงานก่อนทำส่วนที่ขึ้นกับข้อมูลดังกล่าว

ทำแผนที่ความเชื่อมโยงสั้น ๆ หลังอ่าน และทำทะเบียนข้อค้นพบที่ระบุเอกสาร/หัวข้อ/ผู้ใช้ข้อมูล/แหล่งสร้างข้อมูล/จุดเรียกใช้/สถานะจริง/ผลกระทบ/วิธีตรวจ อย่าถือคำว่า verified ในเอกสารเป็นหลักฐานว่าฐานล่าสุดยังมีบัคเดิม ผลตรวจของผู้เขียนคนอื่นเป็นข้อมูลให้ตรวจต่อ

3. ขอบเขตที่ลงมือทำรอบนี้
หมวด 07: 07A–07E การบริหารสำนัก ตำแหน่งและเขตอำนาจ แปดยอดเขา/สถานี อาคาร/ที่พัก/ทรัพยากร การเมือง/สภา/กฎหมาย การสืบทอด เกษียณ และวงจรบริหารตามเอกสาร
หมวด 08: 08A–08F สำนักคู่แข่ง/การทูต/พื้นที่ทรัพยากร การสำรวจ/คาราวาน/ตลาด ดินแดนลับ/เจดีย์ ระบบนิเวศ/สัตว์เลี้ยง/ทรัพยากรป่า ตกปลา/อาหาร/ผู้มาเยือน/เบาะแส และการดำเนินโลกตามเอกสาร

แบ่งลงมือและตรวจเป็นช่วง: ระบบกลางที่จำเป็น → หมวด 07 → หมวด 08 → ตรวจร่วมทั้งสองหมวดและตรวจย้อนหลัง 01–06 เก็บจุดอ้างอิงหรือสำเนาย้อนกลับก่อนเปลี่ยนระบบกลาง แต่ไม่หยุดรออนุมัติทุกข้อหรือส่งเพียงแผนงาน เมื่อจบ 07 ให้ตรวจและบันทึกก่อนต่อ 08 เมื่อจบ 08 ให้ส่ง ZIP ฉบับเต็มก่อนเริ่มรอบอื่น

คุณมีดุลพินิจตรวจและเลือกวิธีแก้เอง รับ ปรับ รวม ทดแทน หรือไม่ใช้ข้อเสนอใดก็ได้โดยอธิบายเหตุผลสำคัญ เอกสารอาจมีข้อเท็จจริงเก่า ข้อเสนอเชิงออกแบบ และปัญหาที่ยังไม่ยืนยันปนกัน ต้องแยกออกด้วยหลักฐานจริง ถ้าปัญหาแก้แล้วให้ตรวจยืนยันและบันทึก ไม่สร้างระบบซ้ำ ไม่ลบหรือปิดระบบเพื่อให้ชุดทดสอบผ่าน

หากพบปัญหาเพิ่มเติมจากเอกสารที่เกี่ยวข้องกับ 07–08 หรือเป็นต้นเหตุ/ผลกระทบโดยตรง ให้ตรวจและแก้ได้เลย รวมถึงแก้ไฟล์ในหมวดอื่นเมื่อจำเป็นเพื่อให้ผลถูกต้องครบวงจร บันทึกการขยายขอบเขตและเหตุผล ส่วนปัญหาที่ไม่เกี่ยวข้องกับงานรอบนี้ให้เก็บเป็นงานค้างเพื่อรอบถัดไป

4. วิธีคิดก่อนและหลังแต่ละการเปลี่ยนแปลง
คิดให้ละเอียด ลึก หลายขั้น หลายมุมและหลายมิติตามความเสี่ยง อย่าหยุดที่จุดผิดจุดแรก ไล่จากผู้สร้างข้อมูล → เงื่อนไข/สิทธิ์/ทรัพยากร → ผู้ตัดสินใจ → การลงมือจริง → การเปลี่ยนสถานะ → ผู้ได้รับผล → เซฟ/โหลดและ UI → ผลสะสมระยะยาวและวงจรย้อนกลับ

พิจารณาอย่างน้อยมุมต่อไปนี้เมื่อเกี่ยวข้อง: ความสนุกและโลกเทพเซียน; แรงจูงใจ/นิสัย/ความรู้ของ NPC; การกระจายอำนาจและความขัดแย้ง; สังคมและการสืบทอด; ตรรกะและบาลานซ์; เศรษฐกิจและการหมุนทรัพยากร; โลกภายนอกและฝ่ายคู่แข่ง; การต่อสู้/การเดินทาง/การบาดเจ็บ/การตาย; ความครบของข้อมูล; การแสดงผลที่ผู้เล่นเข้าใจ; ความคงอยู่ของสถานะและประสิทธิภาพ เลือกมุมที่สัมพันธ์กับปัญหา ไม่ต้องจำลองว่ามีผู้เชี่ยวชาญหรือผู้เล่นจริงมาทดสอบ

ก่อนแก้ให้ตอบในบันทึกงานด้วยหลักฐานว่า: ใครใช้สิ่งนี้? เรียกเมื่อใด? มีทางเข้ากี่ทาง? เงื่อนไขล้มเหลวเป็นอย่างไร? ค่าใดต้องคืนเมื่อยกเลิก/ตาย/ออกจากสำนัก? มีข้อมูลสำเนา cache หรือการประมวลผลทั้งบนแผนที่และนอกแผนที่หรือไม่? แก้ตรงนี้แล้วอะไรเปลี่ยนต่ออีก? เปลี่ยนแล้วผลย้อนกลับจะสร้างความมั่งคั่งฟรี งานค้าง คนหาย ทรัพยากรหาย การยึดครองถาวร หรือวงจรพฤติกรรมผิดหรือไม่?

ตัวอย่างผลลูกโซ่ที่ควรตรวจจริงตามงาน:
- อำนาจตำแหน่ง/นโยบาย → การจัดคนและสิทธิ์ใช้คลัง → ค่าจ้าง/การผลิต → สำรองอาหาร/ยา → ความพร้อมออกสำรวจและตั้งรับ
- การเดินทาง/ทูต/สงคราม → การล็อกกำลังคนและพื้นที่ → การบาดเจ็บ/ตาย/ขนของกลับ → ทรัพยากร/ความสัมพันธ์/การเมือง → การตัดสินใจรอบถัดไป
- การตาย/เกษียณ/ออกจากสำนัก → คืนตำแหน่ง ที่พัก อุปกรณ์ ความรู้ และการจองทรัพยากร → ผู้สืบทอด/สถานะสภา/unique registry → เซฟและเล่นต่อ
- สัตว์ป่า/ทรัพยากร/ตกปลา → เก็บเกี่ยว/ผลิต/ขาย → การเกิดใหม่และความสมดุล → พฤติกรรม NPC และผลในระยะยาว

ตรวจต้นเหตุและทางเลือกก่อนเลือกแก้ อย่าแก้ด้วยตัวเลขชดเชยหรือ fallback ที่ซ่อนความเสียหายโดยไม่มีเหตุผล ไม่เปลี่ยนสิ่งที่เป็นเจตนาการออกแบบให้เป็นบัคเพียงเพราะต่างจากข้อเสนอ

5. หลักของเกมและกฎโครงการ
โลกต้องดำเนินเองและ NPC ตัดสินใจตามสถานะ ความรู้ แรงจูงใจและข้อจำกัด ไม่เพิ่มขั้นตอนที่ผู้เล่นต้องสั่งหรือยืนยันกิจวัตร NPC ผู้เล่นดูข้อมูลและใช้เครื่องมือแก้สถานะ/ตัวเสกตามสิทธิ์ที่กำหนดใน AGENTS.md

รักษา human_core.js และข้อบังคับเรื่อง fingerprint/ลำดับสคริปต์ตาม AGENTS.md เทียบกับฐานที่ถูกต้อง ไม่ใช้ Math.random ในเส้นทางจำลองที่ต้อง deterministic ใช้ RNG ของโลกตามกติกา ไม่แก้ AGENTS.md โดยพลการ หากเอกสารใดเสนอแตะไฟล์ที่ถูกคุ้มครอง ให้หาทางแก้ในขอบเขตที่อนุญาตก่อน และบันทึกข้อจำกัดที่เหลือ

6. หลักฐานและการทดสอบ
ตรวจแต่ละข้อบนซอร์สล่าสุดและทางเรียกจริง กำหนดการตรวจที่พิสูจน์พฤติกรรมและผลกระทบ มีกรณีปกติ ขอบเขต ค่าหาย ไม่มีทรัพยากร คำสั่งล้มเหลว การยกเลิก/ขัดจังหวะ ตาย/เกษียณ/เปลี่ยนฝ่าย และการเรียกซ้ำตามความเกี่ยวข้อง ทดสอบเซฟโหลดระหว่างการดำเนินงานและเล่นต่อ ตรวจการคืนการจอง/ล็อก/ทรัพยากร และความสอดคล้องระหว่างสถานะจริง บันทึก และ UI

เพิ่ม regression ที่จำเป็นสำหรับต้นเหตุที่แก้ รันการตรวจเฉพาะระบบและชุดทดสอบตาม AGENTS.md รวม validator และชุด regression กว้างเมื่อแก้หลายระบบ ใช้การจำลองต่อเนื่องและ seed ที่กำหนดเพื่อดูผลสะสมตามความเสี่ยง บันทึก seed ระยะเวลา จำนวน NPC และข้อจำกัดจริง ห้ามอ้างว่าทดสอบระยะยาวหรือในเบราว์เซอร์แล้วถ้าไม่ได้ทำ หากทำไม่ได้ให้ระบุคำสั่งที่ควรใช้กับสิ่งที่ยังไม่ยืนยัน ไม่แก้เกณฑ์หรือถอดทดสอบเพื่อให้ผ่าน

หลังแก้แต่ละช่วงตรวจว่าไม่ได้ทำให้หมวด 01–06 ที่คุณแก้แล้วกลับมาผิด เมื่อจบทั้งสองหมวด สร้างเกมออฟไลน์จากซอร์สและตรวจชุดส่งมอบตามข้อกำหนด

7. เอกสารส่งต่อและสิ่งส่งมอบ
อัปเดตสรุปเกม สกิล และรายงานที่เกี่ยวข้องในโปรเจกต์ล่าสุดของคุณตาม AGENTS.md รักษาข้อมูลที่คุณอัปเดตในหมวด 01–06 อย่าคัดลอกสกิลหรือสรุปจากชุดอ้างอิงเก่าทับทั้งไฟล์โดยไม่รวมความต่าง

ส่งรายงานหมวด 07–08 ที่ตรวจย้อนกลับได้: ข้อค้นพบต้นทางและเพิ่มเติม, ข้อที่แก้แล้ว/ไม่รับ/ยังค้างพร้อมเหตุผล, ต้นเหตุและผลที่เปลี่ยน, ผลกระทบข้ามระบบ, ไฟล์ที่แก้, คำสั่งและผลทดสอบจริง, ข้อจำกัด และงานต่อไป หากเขียนใบสั่งงานรอบถัดไปตาม AGENTS.md ให้ระบุว่ารอผู้ใช้สั่งเริ่ม

ส่ง ZIP โปรเจกต์ฉบับเต็มที่รวมงานหมวด 01–08 และงานเดิมทั้งหมด มีซอร์สโมดูล assets CSS เกมออฟไลน์ที่ build ตรงกับซอร์ส เครื่องมือ ชุดทดสอบและ dependency ใน repo, AGENTS.md, .agents/skills/, bug reports/ ครบ, สรุปเกม และรายงาน ใส่ directory entries ครบ ไม่ใส่ .git แคชหรือ ZIP ซ้อนที่ไม่จำเป็น ปิดตัวเขียน ZIP แล้วเปิดตรวจ testzip/CRC จริง ทดลองแตกลงโฟลเดอร์ใหม่ เทียบรายการและ hash ไฟล์สำคัญ และตรวจจากไฟล์ที่แตกตามที่ทำได้ก่อนส่ง ไม่ส่งเพียงไฟล์เกมเดี่ยวหรือรายงานแทนโปรเจกต์

ส่งลิงก์ดาวน์โหลด ZIP พร้อมสรุปสั้นให้ผู้ใช้ เมื่อส่งครบแล้วหยุดรอการตรวจและคำสั่งถัดไป ไม่อ้างว่า push GitHub เพราะแชทนี้ไม่มีสิทธิ์เข้าถึง
