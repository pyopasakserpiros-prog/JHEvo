# หมายเหตุเสริมจากการตรวจหมวด 05 สำหรับ Gemini

**สถานะ:** ข้อสังเกตจากการตรวจเทียบเอกสารกับซอร์ส เพื่อให้ Gemini ตรวจสอบและตัดสินใจเอง ไม่ใช่ข้อสรุปที่ผู้เขียนเอกสารต้องรับทั้งหมด และไม่ใช่คำสั่งให้แก้โค้ดตามข้อเสนอโดยอัตโนมัติ

**ฐานที่ตรวจ:** สาขา `main-debug`, commit `eb6224c7035d478f7526c9fa896dbf054bb5345b` ณ วันที่ 2026-11-14 เทียบเอกสาร `05A`–`05G` กับซอร์สใน `GAME_SOURCE/` การตรวจรอบนี้เป็น static review ไม่ได้รันเกมหรือชุดทดสอบ

## 1. ข้อค้นพบใหม่ที่เสนอให้ตรวจใน 05F: สูตรกริชประกาศ ID ไม่ตรงกับ ID ที่สร้างจริง

ใน `GAME_SOURCE/data/data_martial.js` รายการ `procSpecs` สร้างแม่พิมพ์ `ITEM_PROC_DAGGER` โดยกำหนด `subType: 'BLADE'` (บรรทัด 45724, 45739–45747) และสูตร `REC_PROC_DAGGER` ประกาศ `outItemId: ITEM_PROC_DAGGER` แต่ตั้ง `proceduralGearType` เป็น `BLADE` (บรรทัด 45760–45771)

ตอนจบการผลิต `ECO.finishCraft` ส่ง `proceduralGearType` เข้า `ECO.rollProceduralGear` (`GAME_SOURCE/js/economy.js:553–566`) จากนั้นตัวสร้างผลลัพธ์ประกอบ ID ด้วย `'ITEM_PROC_' + gearType` (`economy.js:1670`) ดังนั้นสูตรนี้สร้างไอเท็ม ID `ITEM_PROC_BLADE` ไม่ใช่ `ITEM_PROC_DAGGER` แม้จะประกาศแม่พิมพ์และผลลัพธ์อีก ID ไว้ก็ตาม

ผลต่อเนื่องที่ควรตรวจ:

- แม่พิมพ์ `ITEM_PROC_DAGGER` อาจไม่ถูกใช้กับเส้นทางผลิตปกติ
- `ECO.pickOrder` นับอุปกรณ์ตาม `gearCounts[r.outItemId || r.id]` (`economy.js:1005–1030`) จึงอาจเห็นสูตรกริชว่าผลิตได้ไม่ครบตลอด แม้จะมีผลผลิต `ITEM_PROC_BLADE` อยู่แล้ว แล้วเลือกสูตรกริชซ้ำ
- สูตรกริชและสูตรดาบอาจสร้างอุปกรณ์ประเภทเดียวกัน แต่มีการคาดการณ์ความต้องการในคลังต่าง ID

ขอให้ Gemini ตรวจว่าเจตนาคือให้กริชเป็น alias ของ BLADE หรือเป็นประเภทอุปกรณ์แยกจริง แล้วตัดสินใจเองว่าจะปรับข้อมูลสูตร ระบบสร้างผลผลิต การนับคลัง หรือไม่รับข้อสังเกตนี้

## 2. ตัวเลขความครอบคลุม procedural ใน 05F ควรตรวจนับใหม่

เอกสาร `JS2 v2.6.0 — Equipment Audit (Cat. 05) Verification & Errata.docx` ที่เพิ่งเพิ่มจาก `main` แก้จำนวนสูตรที่ไม่มี `proceduralOut` จาก 5 เป็น 6 แล้ว ข้อสังเกตเพิ่มเติมของการตรวจครั้งนี้คือรายการ `DAGGER` ด้านบนใช้ `gearType: 'BLADE'` ซึ่งซ้ำกับประเภทมาตรฐาน BLADE ใน `ALL_GEAR_TYPES` (`GAME_SOURCE/js/economy.js:1526–1530`) จากการนับทะเบียน procedural ในชุดข้อมูลที่โหลดสำหรับการตรวจ มี 18 สูตรที่ติด `proceduralOut: true` แต่เพียง 17 ประเภท gear มาตรฐานที่ไม่ซ้ำ จาก 23 ประเภท จึงควรแยกการนับ “สูตรที่ตั้ง flag” ออกจาก “ประเภท gear มาตรฐานที่ทำงานได้”.

ตามการนับนี้ ประเภทที่ยังไม่มีสูตร procedural ที่ทำงานในทะเบียนคือ `ROSARY`, `CLAW`, `NEEDLE`, `FAN`, `ASTROLABE` และ `ABACUS` รวม 6 ประเภท ขอให้ Gemini ตรวจเงื่อนไขและขอบเขตการนับกับ catalog ปัจจุบันอีกครั้งก่อนแก้ข้อสรุปใน 05F

## 3. ข้อความเดิมที่ควรทบทวนกับโค้ดปัจจุบัน

### 05B — Bodhi และ Taichi

- ข้ออ้างว่า Bodhi ใช้กับ `BUDDHA_DHARMA` ไม่ได้เพราะขาดจาก `compatiblePath` ยังไม่มีหลักฐานว่าเป็นข้อจำกัดการสวมจริง: ข้อมูลปัจจุบันมี `ANY` ในรายการ และจากการค้นซอร์สไม่พบจุดที่ใช้ `compatiblePath` ปฏิเสธการสวม (`GAME_SOURCE/js/visitors_clues.js:980–981`)
- รายการ `preferredSubs` ของ Taichi ในโค้ดปัจจุบันคือ `BATTLEFIELD_STRATEGIST`, `SECT_STEWARD`, `EARTH_VEIN_WARDEN`, `QIMEN_TALISMAN_PATRON` (`visitors_clues.js:1020–1021`) จึงควรเทียบกับรายการเก่าที่ 05B อ้างก่อนคงข้อกล่าวหาเรื่อง ID ล้าสมัย
- ข้ออื่นของ Bodhi/Taichi เช่น ผลต่อพันธมิตรหรือการทำงานเมื่อใช้ทักษะสนับสนุนเป็นคนละประเด็น และควรตรวจแยกจาก `compatiblePath`

### 05C — จำนวนชาร์จของเครื่องราง

- ข้อความว่า mint wrapper ทิ้ง `charges` ไม่ตรงทั้งหมดแล้ว: `GAME_SOURCE/js/stats.js:1277–1289` คัดลอก `it.charges` ไปยัง gear และกำหนด `maxCharges` เมื่อสร้างเกียร์
- ปัญหาการใช้ชาร์จยังมีขอบเขตที่ควรตรวจต่อ: `ECO.useConsumableItem` ตรวจ `def.maxCharges` (`economy.js:2944–2955`) ส่วน combat item proc ตรวจเพียงว่า `it.charges <= 0` แล้วข้ามผล แต่ไม่พบการหัก `it.charges` ในเส้นทางนี้ (`GAME_SOURCE/js/combat.js:6133–6165`) จึงควรแยกข้อกล่าวเรื่องการ mint ออกจากข้อกล่าวเรื่องชาร์จไม่ถูกใช้

### 05D — cache เมื่ออุปกรณ์สึกหรือแตก

05D เสนอว่า cache ไม่รับรู้ durability break ระหว่างต่อสู้ แต่ `ECO.wearGear` เรียกทำเครื่องหมายค่าสถานะและ invalidate martial cache เมื่อ durability ข้ามช่วงหลักสิบหรือแตก (`GAME_SOURCE/js/economy.js:1844–1847`) จุดนี้อาจถูกแก้หรือมีการ invalidate อยู่แล้วในเส้นทางปัจจุบัน ขอให้ Gemini ตรวจเส้นทางเรียกจริงและทดสอบกรณีแตกกลางศึกก่อนคงข้อสรุปเดิม

### 05G — อุปกรณ์ของผู้ถูกขับไล่/ออกจากสำนัก

ใน `SIM.retire` ปัจจุบัน อุปกรณ์ที่สวมและอุปกรณ์ในกระเป๋าถูกย้ายกลับ `W.sect.gear` (`GAME_SOURCE/js/sim.js:617–618`) และมีการเรียก `VC.syncUniqueArtifacts` ต่อ (`sim.js:653`) ดังนั้นข้อสรุปว่าอุปกรณ์สูญหายเมื่อผ่านเส้นทางเกษียณนี้ไม่ตรงกับโค้ดปัจจุบัน ควรตรวจทุกเส้นทางออกจากสำนักแยกกันก่อนสรุปว่าเป็นปัญหาทั่วทั้งระบบ

## 4. แนวทางใช้หมายเหตุนี้

รายการด้านบนเป็นจุดให้ตรวจซ้ำ ไม่ได้ลบล้างข้อค้นพบอื่นใน 05A–05G Gemini ควรเปิดดูซอร์ส ณ commit ที่ตนใช้ ยืนยันเส้นทางเรียกและผลกระทบต่อเนื่อง แล้วตัดสินใจเองว่าจะรับ ปรับ แยก หรือปฏิเสธแต่ละข้อ รวมถึงจะเขียนกลับเข้า PDF เดิมหรือแก้โค้ดหรือไม่ หากมีการทดสอบ ให้บันทึกผลจริงแยกจากการวิเคราะห์แบบ static
