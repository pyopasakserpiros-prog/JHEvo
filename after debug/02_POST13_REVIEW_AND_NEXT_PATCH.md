# ตรวจรับหลังแพตช์หมวด 01–13 และงานแพตช์ถัดไป

วันที่ตรวจ: 2026-11-15 · เกม JianghuSect 2 JS2-v2.6.0
ฐาน: `main-debug` commit `9a61f6a` (snapshot final-release ที่ผู้ใช้เพิ่งอัปโหลด)

## ผลสรุปและขอบเขตหลักฐาน

ฐานใหม่มีการเปลี่ยนซอร์สจริงหลายระบบ พร้อมชุดทดสอบเฉพาะหมวด 02–13 ไม่ใช่เพียงเพิ่มรายงาน อย่างไรก็ตาม ข้อความใน Final Release ว่าแก้ครบ 100%, อนุรักษ์ศิลาทุกก้อน และไม่มีปุ่มสั่ง NPC เกินกว่าหลักฐานที่ชุดทดสอบพิสูจน์ได้ รอบนี้พบบัคยืนยันได้ 4 กลุ่มและแก้พร้อม regression แล้ว และพบประเด็นระบบที่ต้องทำต่อ

การตรวจนี้เทียบรายงาน BUGFIX_CATEGORIES ทั้ง 6 ฉบับและ Final Release กับจุดเรียกใช้ที่เกี่ยวข้อง รัน regression ทั้งชุด ตรวจ validator/core/build และไล่เส้นทางบริจาค การหลอม รายได้จุดทรัพยากร และการให้คำปรึกษาเพิ่มเติม ไม่ได้ทำตารางปิดข้อค้นพบทุกย่อหน้าใน PDF ต้นฉบับทั้ง 13 หมวด จึงไม่รับรองว่าข้อเสนอทุกข้อในเอกสารได้ถูกแก้หรือถูกปฏิเสธอย่างมีเหตุผลครบแล้ว และไม่ได้ทดสอบเล่นหลายร้อยปีหรือรับรองประสิทธิภาพมือถือจริง

## แก้แล้วในรอบตรวจนี้

### R01 — ป้ายของเสกหายเมื่อบริจาคเข้าคลัง (เกี่ยวข้อง 05/06/10)

หลักฐานก่อนแก้: ให้ NPC มีวัตถุดิบ 10 หน่วย เป็นของเสก 3 หน่วย บริจาค 5 หน่วยผ่าน `ECO.donatePersonalProduct` แล้วจำนวนป้ายของเสกรวมในกระเป๋าและคลังเหลือ 0 แทน 3 แม้การรับแต้มในครั้งนั้นจะกันของเสกแล้วก็ตาม

สาเหตุ: ตัด `npc.inv.spawnedMats/spawnedPills` แต่เรียก `ECO.add` เป็นของปกติ ปัญหาครอบคลุมวัตถุดิบ/โอสถบริจาคโดยตรง การบริจาคอัตโนมัติใน `AI.ACTS.donate.done` และผลิตภัณฑ์โอสถส่วนตัว `playerSpawned`

แก้ใน `GAME_SOURCE/js/economy.js` และ `js/cpeco.js`: โอนส่วนปกติกับส่วนของเสกแยกกันผ่าน API เดิม และคงคุณภาพโอสถ ผลต่อเนื่องคือระบบหลอมที่ตรวจวัตถุดิบเสกยังเห็นแหล่งกำเนิดจริง ไม่ฟอกป้ายผ่านการบริจาค การให้แต้มยังคิดเฉพาะส่วนที่เป็นของปกติ

ตรวจครบ 4 เส้นทาง รวมส่วนผสมปกติ/เสกและ serialize/deserialize ของป้ายในคลัง ก่อนแก้ regression ล้มเหลวจริง หลังแก้ผ่าน

### R02 — จุดทรัพยากรสร้างศิลาจากกองกลางที่หมดแล้ว (เกี่ยวข้อง 07/08/10)

`EXPED.harvestResourceNodes` ใน `js/expedition.js` เคยใช้ rawStones เมื่อ pool.stones เป็น 0 และปัดเศษ pool ด้วย Math.round ทำให้ 0.5 ถูกจ่ายเป็น 1 โดยไม่หักเงินเมื่อยอดกองกลางไม่พอ จึงเพิ่มยอดรวมศิลา

แก้การจำกัดจำนวนให้ใช้จำนวนเต็มที่มีจริง `Math.floor` และไม่จ่ายเมื่อกองกลางไม่เป็นจำนวนจำกัดหรือมีไม่ถึง 1 หน่วย ตรวจ pool 0, 0.5, 1 และ 20 พร้อม invariant ว่าเงินสำนักที่เพิ่ม + เงินกองกลางที่เหลือ เท่ากับยอดเดิม ก่อนแก้กรณีศูนย์ล้มเหลว หลังแก้ผ่านทั้งหมด ไม่ได้เปลี่ยนระบบเกิดวัตถุดิบชนิดอื่นหรือกำหนดนโยบายรายได้ทุกชนิดแทนผู้ใช้

### R03 — Counsel ลดเกจแต่ไม่คลายปมเหตุการณ์จริง (เกี่ยวข้อง 02/11)

`AI.pairEnd` ตรวจและเรียก `SECT.HEART_DEMON.counsel` ซึ่งไม่มีอยู่จริง จึงข้ามเงียบ ๆ ส่วนที่ทำงานมีเพียงลดเกจ -16 และ stress -10 ทดสอบเกจ 70 เหลือ 54 แต่ปม `heartDemons[0].resolved` ยัง false

แก้ให้เรียก API ที่มีจริง `counselHeartDemon(W,a,b,null,{quiet:true})` ตามเจตนาจุดเรียกเดิม คงผลลดเกจของกิจกรรมและใช้กลไกคลายปม/สร้าง daoScar/ผลต่อความสัมพันธ์เดิม ตรวจว่าปมคลายโดยผู้ให้คำปรึกษาที่ถูกคน และให้คำปรึกษาซ้ำไม่สร้าง scar ซ้ำ นี่เป็นการเปลี่ยนพฤติกรรมจริง: เมื่อมีปมค้าง จะได้รับผลคลายปมของระบบเดิมเพิ่มจากการลดเกจทั่วไป

ชุดตรวจใหม่: `GAME_SOURCE/test/post13_economy_review_suite.js` ลงทะเบียนใน `test/run_all.js`

### R04 — หน้าเลือกเจ้าสำนักบังเมนูโหลดก่อนเริ่มเกม (เกี่ยวข้อง 12)

`UI.showStart` เคยซ่อน #start เมื่อกด stLoad เฉพาะตอนมีโลกแล้ว แต่ #start มี z-index 30 ขณะที่ #sheet มี 10 จึงสร้างเมนูโหลดสำเร็จใน DOM แต่ผู้เล่นกดปิด/โหลดไม่ได้ หลังติดตั้งเส้นทาง Chromium/HTTP ที่ใช้ได้ `test/startup_ui.js` ผ่านแค่กรณีแรก แล้วติด timeout ที่การคลิกจริง

แก้ onclick stLoad ให้ซ่อน #start เมื่อเปิดเมนูโหลดทุกครั้ง ส่วน `UI.close` มี logic คืนหน้าเลือกเมื่อไม่มีโลกอยู่แล้ว ทดสอบด้วยชุด startup_ui เดิมผ่านกรณีเลือกผู้สมัครคงเดิมหลังยกเลิก กลับหน้าตั้งต้นเมื่อไปเมนูที่ต้องมีโลก โหลด slot ที่บันทึกไว้ slot เสีย และการนำเข้า เพิ่ม guard ฝั่ง FileReader error/abort/invalid ให้แสดงหน้าเลือกกลับเฉพาะเมื่อไม่มี sheet เปิดอยู่ ป้องกันหน้าเลือกบังปุ่มลองนำเข้าใหม่เมื่อไฟล์แรกเสีย ทดสอบ startup_ui เดิมครบ 7 กรณีผ่าน ไม่เพิ่มสิทธิ์ควบคุม NPC

## งานค้างที่ต้องออกแบบและตรวจเพิ่ม

### N01 — รายได้ภายนอกยังไม่ผ่านการโอนเงินจากต้นทางทุกเส้นทาง (ความสำคัญสูง)

จุดที่ตรวจพบใน `js/expedition.js`: `applySiegeResolution` สาขา PILLAGE เรียก `ECO.earn` เพิ่มศิลาจากค่าที่คำนวณจาก power โดยไม่หักกระเป๋าคู่แข่งหรือ pool ในบล็อกนั้น และยังมี seasonal tribute/รางวัลเหตุการณ์หลายจุดเรียก earn แบบไม่ระบุ fromPool ด้วย ส่วน `ECO.earn` โดยไม่มี opts เพิ่มยอดอย่างตรงไปตรงมา

จึงยังสรุปไม่ได้ว่า closed-loop 100% แม้ Final Release suite จะผ่าน เพราะ suite นับเฉพาะบางกระเป๋าและจำลองเพียง 180 ticks ซึ่งไม่ครอบคลุมเหตุการณ์เหล่านี้ ข้อแก้ R02 ปิดเฉพาะการจ่ายจากจุดทรัพยากรที่อ้าง pool อยู่แล้ว

แนวทางแพตช์: ทำทะเบียน source/sink/transfer ทุกเส้นทาง เลือกว่า loot/tribute/รางวัลต้องโอนจาก treasury ของใคร หรือเป็นการเกิดทรัพยากรที่อนุญาตและบันทึก source ให้ชัด จากนั้นใช้ transfer kernel กับทุกการโอน ตรวจเงินหมด การโอนบางส่วน ทรัพย์สินฝ่ายพ่ายแพ้ และข้อความรางวัลจริง ปรับ invariant ให้รวมทุกกระเป๋าตามระบบจริง ไม่เปลี่ยน earn ให้หัก pool ทุกการเรียกเพราะเสี่ยงหักซ้ำในจุดที่หักต้นทางไว้แล้ว

### N02 — UI ยังมีคำสั่งตัดสินใจแทน NPC (ความสำคัญสูงด้านแนวเกม)

`js/ui.js` ยังสร้างปุ่ม `dispatch-trade-caravan` และ `practice-dual-cultivation`; handler เรียก `SECT.CARAVAN_AUCTION.dispatchTradeCaravan` และ `SECT.practiceDualCultivation` โดยตรง เปลี่ยนสถานะโลกจริง ปุ่มเหล่านี้ไม่ใช่การดูข้อมูลหรือแก้สถานะ/ตัวเสกตามข้อยกเว้น จึงขัดกับข้อความ Final Release เรื่อง autonomy 100% และหลักของ AGENTS.md

แนวทางแพตช์: สำรวจทุก data-do ที่เปลี่ยนโลก ระบุผู้ตัดสินใจ NPC และ trigger อัตโนมัติที่มีอยู่จริงก่อนปรับปุ่มเป็นหน้าดูเหตุผล/ติดตามผล ตรวจว่างานยังเกิดเองเมื่อไม่มีผู้เล่นกด ไม่ควรถอดปุ่มแบบครอบจักรวาลโดยยังไม่ตรวจเส้นทางอัตโนมัติและ UI ที่เกี่ยวข้อง

### N03 — การคืนวัตถุดิบเมื่อ reserveInputs ล้มเหลวอาจเพิ่มสัดส่วนของเสก (ความสำคัญกลาง)

ใน `ECO.reserveInputs` rollback ใช้ `ECO.add(..., taken.count, {playerSpawned:true})` เมื่อ `spawnedUsed > 0` ทำให้คืนทั้งจำนวนเป็นของเสกแม้ใช้ของเสกเพียงบางส่วน ต่างจาก cancelCraft ที่คืน spawnedUsed แยกจำนวน จำเป็นต้องมีกรณี failure injection ให้ take ล้มเหลวหลังหักวัตถุดิบตัวแรก และตรวจ quality/provenance/stockTracker/receipt ไปพร้อมกัน ก่อนเปลี่ยน atomic rollback ให้ครบ ไม่ได้ยืนยันว่ามีเส้นทาง gameplay ปกติที่ทำให้เงื่อนไขนี้เกิดในรอบนี้

### N04 — ต้องมีทะเบียนความครบของ audit รายข้อ
