# 01 — หมวด 01: งานค้างและแผนตรวจต่อหลังแก้บั๊ก

**วันที่ตรวจ:** 2026-11-14  
**โค้ดที่ตรวจ:** `main-debug` ที่ commit `977d9e8`  
**สถานะ:** แก้ไขหลายประเด็นแล้ว แต่ยังมีงานค้างก่อนสรุปว่าหมวด 01 ครบ

## ขอบเขตและหมายเหตุเรื่องสาขา

รายงานนี้อ้างอิงโค้ดใน `main-debug@977d9e8` ซึ่งมีแพตช์แก้ไขหมวด 01 ส่วนโค้ดใน `main` ณ เวลาตรวจอ้างอิง `75dfa75` และยังไม่มีแพตช์โค้ดดังกล่าว การเพิ่มรายงานนี้ลงใน `main` เป็นเพียงการบันทึกรายการงานค้าง ไม่ได้รวมโค้ดแก้ไขจาก `main-debug` เข้า `main`

## สิ่งที่ตรวจพบว่าแก้แล้ว

- จำกัดผลของการฝึก track ต่อระดับวิชาที่ใช้งานได้ โดยระดับวิชาย่อยช่วยข้ามระดับหลักได้ไม่เกินหนึ่งขั้น (`GAME_SOURCE/js/cultivation.js`, `CULT.effectiveTechStage`).
- ปรับตัวคูณและความสามารถของ track ให้แตกต่างตามสายย่อย และต่อโบนัสสำคัญ เช่น ฟื้นปราณ การรับรู้ ศรัทธา และสวนกลับ เข้ากับระบบที่ใช้จริง
- เพิ่มระบบศรัทธาสาย GOD ซึ่งเชื่อมกับชื่อเสียง/อิทธิพลสำนัก ด่านศรัทธา ผลด้านการฝึกและพลัง รวมถึงการเสื่อมขั้นเมื่อศรัทธาหมดต่อเนื่อง
- ปรับค่า XP ของ BODY และ GOD ให้สูงขึ้นจากค่าก่อนแพตช์ ลดความต่างจากสายอื่น
- แก้ปัญหา retrain หลายส่วน เช่น การสำรองอายุขัยและการล้างสถานะบางชนิดเมื่อเปลี่ยนสาย

## ผลตรวจและทดสอบที่มีแล้ว

- ชุดทดสอบใหม่ของแพตช์หมวด 01 ผ่านครบ 14 กลุ่ม
- ตรวจ schema ผ่าน: 43 paths, 286 subpaths และ 1,726 martial techniques; ไม่พบ error หรือ warning
- ตรวจ core lock ผ่าน และสร้างไฟล์เกมเดี่ยวได้
- Regression suite ผ่าน 166 จาก 167 รายการ รายการที่เหลือคือ `startup_ui` หมดเวลา; ไม่พบ assertion failure อื่นในการรันนั้น
- `git diff --check` ผ่าน และ working tree ของ `main-debug` สะอาดหลังการตรวจ

ผลเหล่านี้ยืนยันว่าแพตช์มีการเปลี่ยนโค้ดจริงและไม่พบการถดถอยจากรายการทดสอบส่วนใหญ่ แต่ยังไม่ยืนยันว่าทุกข้อในเอกสารหมวด 01 ได้รับการแก้ครบ

## งานที่ยังต้องทำ

### P1 — ตัดสินและแก้การลดขั้นเมื่อ retrain ภายในสายหลักเดิม

ปัจจุบัน `M.retrainingStage` ใน `GAME_SOURCE/js/retraining.js` ยังคำนวณแบบลดขั้นจำนวนมาก: ขั้น 8 จะเหลือขั้น 4 เมื่อเปลี่ยนสายย่อยใน path เดิม แพตช์เพิ่ม `lifeBonus` เพื่อกันตายจากอายุขัยที่ลดลง แต่ยังไม่ได้เปลี่ยนการสูญเสียขั้นนี้

งานต่อ:

1. ตัดสินใจว่าจะให้เปลี่ยนสายย่อยแล้วลดเพียงหนึ่งขั้น หรือคงขั้นสายหลักไว้แต่รีเซ็ต track/มีช่วงพักปรับลมปราณ
2. เพิ่ม regression test ยืนยันขั้นปลายทางที่ตั้งใจไว้สำหรับผู้ฝึกขั้นต้น กลาง และสูง
3. ตรวจว่าการเปลี่ยนสายย่อยยังล้างโบนัสเฉพาะสายเดิม และไม่ล้างสถานะที่ควรคงอยู่
4. ทดสอบผู้ฝึกสูงวัยว่าไม่ตายทันที และยัง retrain ได้ตามกติกาที่เลือก

### P1 — ยืนยันเวลาจริงในการไปถึงขั้นสูงสุดของ BODY และ GOD

หลังแพตช์ ผลรวมเกณฑ์ XP ที่เห็นใน `CULT.THRESH` คือ XIAN 260,260, BODY 132,000 และ GOD 129,400 XP ตัวเลขนี้ไม่เท่ากับเวลาในเกม เพราะสูตรอัตราฝึก คุณสมบัติ NPC รากพลัง ศรัทธา และกิจกรรมสำนักต่างกัน เอกสารตรวจเดิมตั้งเป้าให้ BODY/GOD ใช้เวลาประมาณ 65–85% ของสายแปดขั้น แต่ยังไม่มีผล simulation ยืนยันเป้าหมายนั้น

งานต่อ:

1. ทำ simulation แบบกำหนด seed ซ้ำได้ เปรียบเทียบ NPC ที่มีคุณสมบัติและทรัพยากรใกล้เคียงกันใน XIAN, BODY และ GOD
2. วัดวัน/เดือนถึงแต่ละขั้นและขั้นสูงสุด ไม่ใช้ผลรวม XP แทนเวลา
3. ทดลองหลาย seed และสถานการณ์ศรัทธา/ชื่อเสียง/ด่านสำนัก เพื่อดูทั้งค่ากลางและกรณีสุดโต่ง
4. ปรับค่าเฉพาะเมื่อผล simulation ยืนยันว่าหลุดจากช่วงเป้าหมาย พร้อมทดสอบผลต่อการเกิดยอดฝีมือ การจัดอันดับสำนัก และการจำลองระยะยาว

### P1 — เพิ่ม regression test เฉพาะการป้องกันข้ามระดับจาก track

โค้ดจำกัดโบนัสระดับวิชาแล้ว แต่ยังไม่พบ test ที่ยืนยันตรงกับ exploit หลักในเอกสาร

เกณฑ์ทดสอบที่ควรเพิ่ม:

- NPC ขั้น 1 ที่มี `track.ordinal` สูง เช่น 8 ต้องได้ `effectiveTechStage` ไม่เกิน 2
- NPC ขั้น 1 ต้องใช้/ซื้อ/เรียนอุปกรณ์หรือวิชาขั้น 7 ไม่ได้
- การประเมิน subpath traits ต้องใช้ระดับที่ถูกต้องเมื่อ `track.ordinal` เป็น 1 และเมื่อ NPC อยู่ขั้นสูง
- ครอบคลุม path ที่มี 4, 5, 8 และ 9 ขั้น รวมกรณีไม่มี track และมี track

### P1 — เพิ่ม test วงจรศรัทธา GOD ตั้งแต่ปกติจนเสื่อมขั้น

มีการเพิ่ม gate และผลของศรัทธาแล้ว แต่ยังไม่พบ test ที่เจาะวงจรนี้โดยตรง

เกณฑ์ทดสอบที่ควรเพิ่ม:

- ตรวจ gate ขั้น GOD เมื่อศรัทธา/ชื่อเสียง/จำนวน outpost อยู่ก่อนและหลังค่าที่กำหนด
- ตรวจว่า shrine, ผลงานช่วยเหลือ, distress calls และการกระทำของ NPC ส่งผลต่อ pool ตามสูตรที่ตั้งใจ
- ตรวจผลศรัทธาต่ำต่ออัตราฝึกและพลัง และการเสื่อมขั้นหลังศรัทธาเป็นศูนย์ต่อเนื่อง
- ตรวจ save/load และกรณี NPC ไม่มี world/sect context เพื่อไม่ให้ค่าศรัทธาค้างหรือกลายเป็น gate ที่ผ่านไม่ได้

### P2 — หาสาเหตุ `startup_ui` timeout

การรัน regression ล่าสุดค้างจนหมดเวลาเฉพาะ `startup_ui` ขณะที่รายการอื่นผ่าน งานต่อคือรันรายการนี้แยก ตรวจว่าเป็นข้อจำกัดของ runner/browser หรือเป็นปัญหาจากแพตช์ และบันทึกผลจริงก่อนสรุปชุดทดสอบว่าเขียวครบ

### P2 — ปิดงานเอกสารส่งต่อแพตช์

แพตช์แก้โค้ดเปลี่ยนหลายระบบ แต่ยังไม่อัปเดต `project_status_and_ai_onboarding.md`, สกิลที่ได้รับผลกระทบใน `.agents/skills/` และรายงานแพตช์ตามที่ `AGENTS.md` กำหนด

งานต่อ:

- อัปเดตสรุปโครงการและสกิล cultivation, combat/stats, retraining และ simulation ตามขอบเขตที่เปลี่ยน
- เพิ่มผลทดสอบ ข้อจำกัด และสถานะที่ยังไม่ยืนยันในรายงานแพตช์
- ตรวจว่าข้อมูลในเอกสารตรงกับโค้ดและ test จริง โดยแยก “แก้แล้ว”, “ยังไม่ยืนยัน” และ “งานอนาคต”

## เกณฑ์ปิดหมวด 01

ให้ปิดหมวดเมื่อแก้หรือระบุการตัดสินใจสำหรับ retraining ภายในสายเดิมแล้ว, มีผล simulation ยืนยันสมดุล BODY/GOD, มี regression tests สำหรับ effective stage และ faith lifecycle, `startup_ui` ผ่านหรือมีสาเหตุ/ข้อจำกัดที่ยืนยันแล้ว และเอกสารโครงการกับสกิลได้รับการอัปเดตครบตาม `AGENTS.md`.
